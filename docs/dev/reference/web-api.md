# Web API

The HTTP API of `agboard serve`. How a request is handled, including the write guard, is described in [Server and web UI](../concepts/server-and-ui.md).

Task writes accept optional `X-Agboard-Language: en` or `ja` for generated history. The board and monitor send their current UI language. Missing, repeated, or unsupported values fall back to the task body’s language. This affects only generated text for that request; explicit reasons and stored history stay unchanged. See [History](../concepts/history-and-decisions.md#history).

## Endpoints

| API | Contract |
| --- | --- |
| `GET /` | HTML with the write token in `meta[name=agboard-token]`. |
| `GET /api/projects` | `projects` (id, name, createdAt) and `catalogVersion`, without tasks. 200 even when empty. |
| `GET /api/projects/{projectId}/board` | project, version, cursor, epics, `epicTaskCounts` (per epic: todo, doing, done, archived, total; archived counts only as archived; all from the same snapshot), unarchived tasks with bodies and full history, problems. No `nextTaskId`. |
| `POST /api/projects/{projectId}/tasks` | Creates a Todo/Idle task from title, body, acceptance, assignee, isDraft. The server composes and validates the frontmatter. 201. |
| `POST /api/projects/{projectId}/tasks/multipart` | Creates a regular task with images, or an AI task from a short request with its optional epic and images, in one multipart submission. See below. |
| `PATCH /api/projects/{projectId}/tasks/{id}` | Updates title, body, acceptance, and optional `finalize: true` on a **draft** task. Body alone keeps the frontmatter; acceptance alone keeps the body; `description` with `body` is 422 `invalid_value`. Last write wins. Non-draft is 409 `task_not_draft`. |
| `PUT /api/projects/{projectId}/tasks/{id}/draft` | Sets `isDraft`. A running task is 409 `invalid_state_for_draft`. |
| `PUT /api/projects/{projectId}/tasks/{id}/epic` | `{epicId: string \| null}`. Unknown EPIC-ID is 404 `epic_not_found`. |
| `POST /api/projects/{projectId}/tasks/{id}/move` | `taskStatus` and optional `reason`. |
| `POST /api/projects/{projectId}/tasks/{id}/answer` | `requestId`, optional `choiceId` and `text`, matched under the lock. Both empty is 422; an unknown choice is 422 `request_choice_unknown`; a changed request is 409 `request_changed`. |
| `POST /api/projects/{projectId}/tasks/{id}/agent-status` | Changes the run state within the state rules. The UI has no entry point for it. |
| `DELETE /api/projects/{projectId}/tasks/{id}` | Deletes archived tasks only; others are 409 `task_not_archived`. 204, or 404 when already gone. |
| `…/tasks/{id}/attachments`, `…/attachments/{attachmentId}` | Task images (GET, POST, DELETE), matched by ProjectId, task ID, and attachment ID. |
| `GET`/`POST /api/projects/{projectId}/epics` | List and create epics (id, name, color, isDraft, document or body). No `acceptance` input. 201. |
| `GET`/`PATCH`/`DELETE /api/projects/{projectId}/epics/{epicId}` | Read, or update name, color, isDraft, document or body, and priority. Keeps the body and unknown metadata. Saves `EPIC.md` before `epic.json`. `DELETE` answers 204; it is refused with 409 `epic_in_use` while any task, archived ones included, names the epic. |
| `…/epics/{epicId}/attachments`, `…/{attachmentId}` | Epic images. |
| `POST …/tasks/{id}/archive`, `POST …/tasks/{id}/restore` | No body. Repeating either on a task already in that state returns the same task unchanged. |
| `POST …/tasks/archive-done` | `{ids: number[]}`; empty, duplicate, or invalid IDs are 422. Returns `{tasks, archivedCount}`. |
| `GET /api/projects/{projectId}/archive` | Archived tasks with bodies, full history, and attachment metadata, plus `epics` from the same snapshot. Each task's `epicId` resolves against that list; a task without an epic, or one whose epic is missing, has no label. |
| `GET /assets/{name}` | Only the content-named scripts and stylesheets listed in the table generated by `build.rs`; others are 404. Immutable caching, gzip when `Accept-Encoding` allows it, `Vary: Accept-Encoding`. |
| `GET /api/events` | SSE: `ready` after subscribing with the board's build ID (`{"build":"<16 hex>"}`), `changed` on version changes, a keep-alive comment every 15 seconds. |
| `POST /api/notify` | Asks every client to re-fetch. Changes no data and needs no token. 204. |
| `GET /api/health` | `ok` and `pid`. |
| `GET /api/monitor-connections` and the routes under it | The ngrok mobile connection. See [Mobile connection](#mobile-connection). |

### Mobile connection

These routes exist only on the local listener (`127.0.0.1`); the ngrok entry never serves them. A read must come from the local page: a foreign Host, cross-site `Sec-Fetch-Site`, or foreign Origin is 403. The writes pass the same browser write guard as other writes.

| API | Contract |
| --- | --- |
| `GET /api/monitor-connections` | The current state, described below. Never holds a secret. |
| `PUT /api/monitor-connections/settings/ngrok` | Saves `{enabled, allowEmails, domain, oauthApp, revision}` and returns the state. `domain` may be omitted or `null`; `oauthApp` is `managed` or `custom`; `revision` must be the one last read. Unknown fields are 422 `invalid_value`; a stale revision is 409 `revision_conflict`; a failed save is 500 `save_failed` and changes nothing. Saving while the tunnel runs replaces it. |
| `POST /api/monitor-connections/transports/ngrok/start` | Starts the connection and answers 202 with the state (usually `starting`). The optional body is `{token, save}`. `token` is held in memory only; `save: true` also stores it in the OS keychain and needs a `token`. A disabled setting is saved as enabled first. |
| `POST /api/monitor-connections/transports/ngrok/stop` | Stops the connection, saves it as disabled, and answers 200 with the state. |
| `DELETE /api/monitor-connections/token` | Removes the token saved in the keychain and answers 200 with the state. Removing nothing is not an error. |

The state object has these fields:

| Field | Meaning |
| --- | --- |
| `status` | `disabled`, `needs_config`, `starting`, `ready`, `reconnecting`, `failed`, or `stopping`. |
| `url` | The public HTTPS address once `ready`; otherwise `null`. |
| `revision` | The settings revision, for `PUT`. |
| `settings` | `enabled`, `allowEmails`, `domain`, `oauthApp`. |
| `tokenConfigured` | Whether a start would find a token. |
| `tokenSource` | `env` (`NGROK_AUTHTOKEN`), `keychain`, `session` (typed for this run), or `null`. Never the value. |
| `keychainAvailable` | Whether this PC can save a token in the OS keychain. |
| `keychainTokenSaved` | Whether a token is saved in the keychain, even if another source is used. |
| `failure` | `null`, or one of `connect_failed`, `endpoint_failed`, `public_url_invalid`, `internal`, `config_unreadable`, `config_invalid`. |

A start reports its progress through this state; poll `GET` until `status` leaves `starting`. The token, the allow list policy, the proof, and sessions never appear in any response or in the settings file. The settings are stored as described in [Shared files](./files.md#monitor-connection-settings). The error codes are in [Error codes](./errors.md#mobile-connection).

### Multipart task creation

`POST /api/projects/{projectId}/tasks/multipart` accepts exactly one `metadata` part containing JSON and zero or more `file` parts. Each file must have a matching `{id, name}` entry in `metadata.attachments`; normal attachment count, size, and media-type limits apply. For a regular task, metadata includes `requestId`, `title`, `description`, `assignee`, and optionally `isDraft`. For the short request form, send:

```json
{
  "requestKind": "simple",
  "description": "First line becomes the title\n\nFull request details",
  "epicId": "DESIGN",
  "attachments": [{"id": "<attachment-id>", "name": "sketch.png"}]
}
```

`epicId` and `attachments` are optional; omit the epic or use `null`, and use an empty attachments array when there are no images. A simple request accepts no `title`, `assignee`, `isDraft`, or `finalize` metadata. The server creates an AI-owned Todo task, wraps the original text in `## 元の依頼`, and derives the title from the first non-empty line (up to 100 Unicode characters). It validates and stages the task and its images under the project lock, then publishes them together by renaming the completed task directory. Every accepted submission creates a new task and returns `201 {"task": …}`; the server does not compare content to detect duplicates. A normal manually created task continues to use `POST /tasks` or the regular multipart metadata; it does not become a simple request.

**Bulk archive.** The target IDs are fixed when the confirmation opens; the request never re-collects all Done tasks. Under the lock every unarchived target must still be Done. If any target moved or was deleted, the whole request is 409 `archive_targets_changed` and nothing changes. Targets that are already archived count as done, so a retry after a lost response never duplicates history. Targets are saved one at a time with a single reload and notification at the end; if a save fails partway, the saved targets stay archived and a retry handles the rest.

**Errors** carry `code`, `message`, and `reason`:

| Status | Meaning |
| --- | --- |
| 400 | Malformed JSON. |
| 403 | A guard failed. |
| 404 | Project, task, or epic not found. |
| 409 | `request_changed`, `task_not_draft`, `invalid_state_for_draft`, `epic_in_use`, `epic_id_taken`, `task_not_archived`, `archive_targets_changed`. |
| 413 | Body over 1 MiB. |
| 422 | Invalid ID syntax, input, or state rule; or an invalid source file (`file_invalid`) with path, field, and reason. |
| 503 | The lock wait timed out. |
| 500 | Anything else, including `format_unsupported`, `file_unreadable`, and `file_error`. |
