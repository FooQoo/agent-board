# Web API

The HTTP API of `agboard serve`. How a request is handled, including the write guard, is described in [Server and web UI](../concepts/server-and-ui.md).

## Endpoints

| API | Contract |
| --- | --- |
| `GET /` | HTML with the write token in `meta[name=agboard-token]`. |
| `GET /api/projects` | `projects` (id, name, createdAt) and `catalogVersion`, without tasks. 200 even when empty. |
| `GET /api/projects/{projectId}/board` | project, version, cursor, epics, `epicTaskCounts` (per epic: todo, doing, done, archived, total; archived counts only as archived; all from the same snapshot), unarchived tasks with bodies and full history, problems. No `nextTaskId`. |
| `POST /api/projects/{projectId}/tasks` | Creates a Todo/Idle task from title, body, acceptance, assignee, isDraft. The server composes and validates the frontmatter. 201. |
| `PATCH /api/projects/{projectId}/tasks/{id}` | Updates title, body, acceptance, and optional `finalize: true` on a **draft** task. Body alone keeps the frontmatter; acceptance alone keeps the body; `description` with `body` is 422 `invalid_value`. Last write wins. Non-draft is 409 `task_not_draft`. |
| `PUT /api/projects/{projectId}/tasks/{id}/draft` | Sets `isDraft`. A running task is 409 `invalid_state_for_draft`. |
| `PUT /api/projects/{projectId}/tasks/{id}/epic` | `{epicId: string \| null}`. Unknown EPIC-ID is 404 `epic_not_found`. |
| `POST /api/projects/{projectId}/tasks/{id}/move` | `taskStatus` and optional `reason`. |
| `POST /api/projects/{projectId}/tasks/{id}/answer` | `requestId`, optional `choiceId` and `text`, matched under the lock. Both empty is 422; an unknown choice is 422 `request_choice_unknown`; a changed request is 409 `request_changed`. |
| `POST /api/projects/{projectId}/tasks/{id}/agent-status` | Changes the run state within the state rules. The UI has no entry point for it. |
| `DELETE /api/projects/{projectId}/tasks/{id}` | Deletes archived tasks only; others are 409 `task_not_archived`. 204, or 404 when already gone. |
| `…/tasks/{id}/attachments`, `…/attachments/{attachmentId}` | Task images (GET, POST, DELETE), matched by ProjectId, task ID, and attachment ID. |
| `GET …/tasks/{id}/evidence/{evidenceId}` | Task evidence as `text/plain; charset=utf-8`. |
| `GET`/`POST /api/projects/{projectId}/epics` | List and create epics (id, name, color, isDraft, plan or body). No `acceptance` input. 201. |
| `GET`/`PATCH`/`DELETE /api/projects/{projectId}/epics/{epicId}` | Read, or update name, color, isDraft, plan or body, and priority. Keeps the body and unknown metadata. Saves `PLAN.md` before `epic.json`. `DELETE` answers 204; it is refused with 409 `epic_in_use` while any task, archived ones included, names the epic. |
| `…/epics/{epicId}/attachments`, `…/{attachmentId}` | Epic images. |
| `POST …/tasks/{id}/archive`, `POST …/tasks/{id}/restore` | No body. Repeating either on a task already in that state returns the same task unchanged. |
| `POST …/tasks/archive-done` | `{ids: number[]}`; empty, duplicate, or invalid IDs are 422. Returns `{tasks, archivedCount}`. |
| `GET /api/projects/{projectId}/archive` | Archived tasks with bodies, full history, and attachment metadata, plus `epics` from the same snapshot. Each task's `epicId` resolves against that list; a task without an epic, or one whose epic is missing, has no label. |
| `GET /assets/{name}` | Only split assets listed in the table generated by `build.rs`; others are 404. Immutable caching. |
| `GET /api/events` | SSE: `ready` after subscribing, `changed` on version changes, a keep-alive comment every 15 seconds. |
| `POST /api/notify` | Asks every client to re-fetch. Changes no data and needs no token. 204. |
| `GET /api/health` | `ok` and `pid`. |

**Bulk archive.** The target IDs are fixed when the confirmation opens; the request never re-collects all Done tasks. Under the lock every unarchived target must still be Done. If any target moved or was deleted, the whole request is 409 `archive_targets_changed` and nothing changes. Targets that are already archived count as done, so a retry after a lost response never duplicates history. Targets are saved one at a time with a single reload and notification at the end; if a save fails partway, the saved targets stay archived and a retry handles the rest.

**Errors** carry `code`, `message`, and `reason`:

| Status | Meaning |
| --- | --- |
| 400 | Malformed JSON. |
| 403 | A guard failed. |
| 404 | Project, task, or epic not found. |
| 409 | `request_changed`, `task_not_draft`, `invalid_state_for_draft`, `epic_in_use`, `epic_id_taken`, `task_not_archived`, `archive_targets_changed`. |
| 413 | Body over 1 MiB. |
| 422 | Invalid ID syntax, input, or state rule; or an invalid source file (`file_invalid`) with path, field, and reason. |
| 503 | The lock wait timed out. |
| 500 | Anything else, including `format_unsupported`, `file_unreadable`, and `file_error`. |
