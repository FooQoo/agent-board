# 履歴と判断依頼

操作や進捗を残す履歴、人に尋ねる質問と回答、受入条件に基づく自動完了の仕組みを説明します。

## 質問と回答

質問はタスクではなくプロジェクトに属します。エージェントは`agboard qa ask`で質問の束を出し、タスクは待っている質問を参照します。

- 1回の`qa ask`で、`qa/<request-id>/request.json`に1件のリクエストを保存します。リクエストには1〜20問を入れ、まとめて答えてもらいます。リクエストIDは32桁の小文字16進です。各質問には`project.json`の`nextQuestionId`からプロジェクト内の連番`Q-<n>`を振ります。番号は増えるだけです。
- 質問は1〜5,000文字のMarkdownで、2〜10件の選択肢を持ちます。各選択肢は質問内で一意のID（`[A-Za-z0-9_-]`の1〜64文字）と1〜200文字のラベルを持ちます。`kind`は`task`（既定）、`plan`、`start_approval`のどれかです。`recommendedChoiceId`は任意で、選択肢のどれかを指します。`start_approval`の質問には`approvingChoiceIds`が1件以上必要で、ほかの種類には付けません。
- `--task <id>`または質問の`tasks`を指定すると、そのタスクのfrontmatterの`questions`に質問IDを足し、質問と選択肢を別々のブロックにした履歴を追加します。Runningのタスクは同じ保存でIdleに戻します。指定したタスクが存在しない、アーカイブ済み、下書き、またはAIの操作でDoneのときは、何も書きません。
- 回答は`choiceId`、`text`（前後の空白を除いて1〜2,000文字）のどちらか、または両方を受け付け、どちらもないものは拒否します。未知の選択肢は`request_choice_unknown`です。回答は選択時のラベル、`actor`（常に`human`）、`via`（ボードとモバイルモニターからは`ui`、チャットで受けた回答をエージェントが記録したときは`chat`、端末からは`cli`）とともに質問に保存します。質問を参照しているアーカイブされていないタスクには、質問・選んだラベル・メモを別々のブロックにした履歴を追加します。Doneのタスクにも追加します。
- 最初に記録した回答が確定します。回答済みの質問に答えると`question_answered`、取り下げたリクエストの質問に答えると`question_withdrawn`で失敗します。まとめて送った回答は、全部書くか何も書かないかのどちらかです。
- `qa withdraw`はリクエスト全体を取り下げます。理由は任意で2,000文字までです。すでに付いた回答は残ります。全問に回答済みのリクエストは取り下げられません（`request_answered`）。レーンの移動、アーカイブ、削除で質問が取り下げられることはありません。
- `qa link`と`qa unlink`は、タスクの`questions`に参照を足したり外したりします。`TASK.md`の編集と同じ制限がかかり、履歴を追加します。
- 質問と回答の文は前後の空白を除き、CRLFと単独のCRをLFに正規化します。

質問は、回答されるかリクエストが取り下げられるまで`open`です。全問に回答があるリクエストは`answered`です。これらの状態は保存せず、ファイルを読むときに導きます。

### 人の判断待ち

タスクが人の判断待ちになるのは、参照している質問に`open`のものがあるとき、参照している`start_approval`の質問が`approvingChoiceIds`にない選択肢で答えられたとき、参照を確かめられないとき（`request.json`が壊れている、またはfrontmatterの`questions`が壊れている）です。取り下げた質問では待ちになりません。すべてのリクエストのファイルが読める状態で、存在しない質問を指す参照も待ちにはならず、`problems`に載せます。

`task.json`に保存するのは`idle`か`running`だけです。TodoかDoingのAIタスクが判断待ちのときは、Summary、snapshot、`show`、進捗表、hookのどれも`agentStatus`を`pending`として返し、`openQuestionIds`と、IDが最も小さい未回答の質問から`pendingReason`と`pendingChoices`を返します。判断待ちの間、AIによる`state <id> running`とDoneへの移動は`questions_unanswered`で失敗します。`idle`への変更と人の移動は通します。Done、アーカイブ済み、人のタスクは保存した状態を表示し、参照は記録として残ります。

ワークフロー情報を履歴の文章から推測することはありません。質問と回答は`request.json`から、参照はfrontmatterの`questions`から読むので、履歴を編集してもこれらは変わりません。

## 履歴

履歴には、作業の進捗とタスクの操作を時系列で記録します。各項目は、保存・API・CLIのどこでも、次の二つのフィールドだけを持ちます。

- `at`: 厳密に`YYYY-MM-DDTHH:MM:SSZ`の形のUTCの日時。
- `reason`: 1〜10,000文字で、空白だけではない内容。

ID・種別・actor・遷移・依頼IDなどの追加の項目は拒否します。

- 作成・列移動・稼働状態の変更・質問・回答・取り下げ・参照の変更・下書きの切り替え・エピックの変更・アーカイブ・復元・人による条件の付け外し・自動Doneは、履歴を自動で追加します。移動や状態の変更で理由を省くと、操作と現在の状態から生成します。
- エージェントは`agboard --project NAME history add ID [--reason TEXT | --reason-file PATH]`で作業の進捗を追加します。日時はAgent Boardが自動で付け、下書き・アーカイブ済み・DoneのタスクへのAIの追加は拒否します。空白の理由は、現在のレーンと稼働状態から生成します。
- エージェントは、開始・意味のある進捗・判断・検証・中断・再開のときに、記録ごとの承認を求めずに簡潔な項目を記録し、操作時に自動で記録された履歴は重複して追加しません。
- 画面は日時と内容だけを新しい順に表示し、理由は本文と同じMarkdownで描きます。CLIの`show`とスナップショットは全履歴を返します。

ブラウザ操作で自動生成する履歴は、そのリクエストで送られた画面の言語設定（`en`または`ja`）を使います。有効な設定がない操作、CLI操作、自動Doneでは、最新のタスク本文に日本語の文字があれば日本語、それ以外は英語を使います。本文が空か標準テンプレートのままならタイトルを使います。frontmatterと過去の履歴は判定に含めません。明示された空でない理由はそのまま保存し、既存の履歴を翻訳し直すことはありません。

AIが書く履歴は本文と同じ言語にし、理由を明示します。手順は[エージェント連携](./agents.md)で定めています。

## 受入条件と自動Done

管理対象の受入条件を持つのは`TASK.md`だけで、履歴と一緒にfrontmatterに置きます。

```markdown
---
acceptance:
  - id: AC-1
    text: List tasks as JSON.
    done: false
history: []
---

(Task plan, verification results, references to artifacts)
```

- `acceptance`はリストで、省略・`null`・空はどれも0件です。各項目はちょうど`id`（先頭に0を付けない`AC-<正の整数>`、ファイル内で一意）、`text`（前後の空白を除いて1〜2,000文字）、`done`（真偽値）を持ちます。番号は振り直しません。
- ほかのトップレベルのキーは保存時に保ちます（YAMLの書式は正規化されることがあります）。frontmatterのないファイルや、見出しと`- [ ] AC-n.`の行による旧形式は条件0件として読み、移行しません。
- 本文には計画・簡潔な検証結果・成果物への参照を書き、時系列の進捗は`history`だけに書きます。

**自動Done**: AI担当・下書きでない・未アーカイブのTodoかDoingのタスクで、有効な条件が1件以上あり、すべて`done: true`になると、タスクは自動でDoneに移ります。履歴に一件記録し、`taskStatusChangedAt`を更新します。人の判断待ちのタスクは飛ばし、回答が届いたら評価し直します。条件がない・不正なタスク、人間担当、下書きは対象外です。`serve`は起動時にも既存のタスクを評価します。

**人によるチェック**: 人は、ボードかモバイルモニターから、条件を1件ずつ付け外しします（`PUT .../tasks/{id}/acceptance/{condition}`に`{"done": true|false}`を送ります。[Web API](../reference/web-api.md)を参照）。要求に版は含めません。FileStoreは、プロジェクトのロックの中で最新の`TASK.md`を読み、その条件だけを変え、履歴を一件足して保存します。そのため、読み込んだあとに加えられた変更より人の選択が優先され、本文・ほかの条件・エージェントのほかの編集は残ります。アーカイブ済みのタスクは拒否し（`task_archived`）、存在しない条件は`invalid_argument`です。そのあとwatcherが、ほかの変更と同じく自動Doneを評価します。そのため、対象のAIタスクで最後の条件にチェックが入るとDoneに移り、Doneのタスクで条件を外してもDoneのままです。

DoneのタスクはAIの変更（編集・状態・エピック・履歴・画像）を拒否し、自動で再開することはありません。人は編集も再開もできます。未達成の条件が残る、またはfrontmatterが不正なとき、AIの列移動によるDoneへの移動は`acceptance_unmet`で、人の判断待ちのあいだは`questions_unanswered`で拒否します。条件0件のタスクと人の移動は止めません。評価の仕組みは[エージェント連携](./agents.md#自動done)にあります。
