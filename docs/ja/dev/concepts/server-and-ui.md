# サーバーと画面

`agboard serve`は、JSON APIと更新通知を提供し、バイナリに埋め込んだReactアプリでボードを表示します。このページでは、リクエストの処理、画面の構成、エラー発生時の動作を説明します。エンドポイントは[Web API](../reference/web-api.md)にあります。

## serveの起動と停止

データ領域ごとにサーバーは一つまでです。動き方は二通りあり、`serve.json`の`mode`に記録します。

- **自動**　サーバーがないと動かないコマンドが、裏でサーバーを起動します。対象は`wait --after`、`wait --until task`、`--no-wait`を付けない`message ask`、未回答の質問を待つ`message wait`です。エージェントのHookも、待たずに起動します。使われなくなると、サーバーは自分で止まります。
- **手動**　人が`agboard serve`（前面）か`agboard serve -d`（裏）で起動します。Ctrl+Cか`agboard stop`まで動き続けます。

ほかのコマンドはファイルだけで動き、サーバーを起動しません。

### 起動

- `serve`は`127.0.0.1`だけで待ち受け、プロジェクトが0件でも動きます。空のデータ領域には`workspace.json`を作ることがあります。
- データ領域ごとにサーバーが一つだけ動くよう、`lifecycle.lock`（標準の`try_lock`）を起動から終了まで保持します。ファイルがあるだけでサーバーが動いているとは判断しません。ロックはプロセスの終了で外れます。自動のサーバーは、終了処理中のサーバーがロックを外すのを最大10秒待ちます。
- 起動時に`serve.json`があり、そのポートの`GET /api/health`が同じ`pid`を返すなら、`serve`は`already_serving`で終了します。そうでなければ古いファイルとして上書きします。動いているサーバーが自動なら、理由には動かし続けるための`agboard serve -d`を示します。
- `serve -d`は先に同じ確認をします。動いているサーバーが自動で、それと食い違う`--port`や`--monitor`の指定がなければ、そのサーバーにSIGUSR1を送ります。同じプロセスが`mode: "manual"`を記録し、使われていない時間を数えるのをやめます。接続はどれも切れません。それ以外の場合、ターミナルで人が実行していれば、動いているサーバーを`stop`と同じ手順で止めて起動し直すかどうかを尋ね、`--json`を付けたときやターミナルの外では`already_serving`で終了します。
- `serve`は待ち受けを始めた後に`serve.json`（`pid`・`port`・`started_at`・`mode`、自動のサーバーでは`idleTimeoutSeconds`も）を書きます。SIGINTかSIGTERMを受けると、自分のpidが書かれている場合だけ`serve.json`を消します。

### コマンドがサーバーを起動する手順

1. `serve.json`を読みます。そのサーバーがヘルスチェックに応えれば、それを使います。
2. `serve.json`のpidが生きていて`lifecycle.lock`を持っているのに応えないときは、起動中か終了中の場合に備えて最大10秒待ち、そのpidを示した`board_unavailable`で失敗します。二つ目のサーバーは起動しません。OSやサンドボックスが接続を拒んだときは`local_network_denied`です。
3. それ以外なら`autostart.lock`を取ります。ほかのコマンドが起動中なら最大40秒待ち、もう一度確かめます。
4. `agboard --json serve --auto`を新しいセッション（`setsid`）として起動します。作業ディレクトリはデータ領域、標準出力と標準エラーは`serve.log`（起動のたびに空にし、権限は0600）です。子プロセスは開いたままの`autostart.lock`を受け継ぎ、準備ができてから外すので、その間にほかのコマンドが二つ目を起動することはありません。
5. `serve.log`に起動の行が出るまで最大30秒待ち、標準エラーに1行出して続けます。標準出力はコマンド本来の出力のままです。

```text
Started the Agent Board server at http://127.0.0.1:7420/ in the background. It stops by itself after 30 minutes without use.
```

`serve.json`を読んだ後に接続が失敗したとき（その間にサーバーが止まったときなど）は、もう一度だけ起動します。Hookは待たずに起動します。確かめるのは`serve.json`のpidが生きているかと`autostart.lock`が空いているかだけで、`agboard stop`の後は起動しません（後述）。失敗は`serve.log`に残ります。

`AGBOARD_AUTOSTART=0`にすると、これらはすべて止まります。コマンドはこれまでどおり`board_unavailable`を返し、Hookは何も起動しません。ライブラリが自分でサーバーを起動することはなく、起動するのは`agboard`のコマンドラインだけです。

### ボードを開く {#opening-the-board}

自動のサーバーは、起動のきっかけになったプロジェクトのボードを一度だけ開きます。利用者から見た決まりは[CLIリファレンス](../../guide/reference/cli.md#open-the-board-in-the-browser)にあります。

- サーバーを起動するコマンドは、隠しオプション`serve --auto --open-board=<projectId>`でプロジェクトIDを渡します。待つコマンドは待っているプロジェクト、`message ask`と`message wait`は質問のプロジェクト、Hookは出力した進行表のプロジェクトを渡します。`agboard open`は自分でページを開くので、何も渡しません。
- サーバーの準備ができて`autostart.lock`を外した後、スレッドが3秒待ちます（試験では`AGBOARD_OPEN_GRACE_MS`で変えられ、上限は60,000ミリ秒）。起動してからボードのページが一度もつながっていなければ、`http://127.0.0.1:<port>/?project=<projectId>`を開きます。つながってから閉じたタブも、つながり直すかもしれないので数に入れます。
- ボードのページとは、`X-Agboard-Wait`ヘッダーのない`GET /api/events`のストリームです。待つコマンドはこのヘッダーを付けるので、起動の直後に開く自分のストリームがタブと取り違えられることはありません。スマホのページがngrokの入口を通して開くのは、sessionの背後にある同じストリームで、同じように数えます。
- ブラウザーを開けるかどうかは`src/interact/browser.rs`が次の順で決めます。`AGBOARD_OPEN_BROWSER=0`なら開きません。`AGBOARD_BROWSER_OPENER`があれば、そのプログラムをシステムのものの代わりに使います。`SSH_CONNECTION`か`SSH_TTY`があれば開きません。macOSとWindows以外では、`DISPLAY`も`WAYLAND_DISPLAY`もなければ開きません。それ以外なら`open`（macOS）、`explorer`（Windows）、`xdg-open`を、アドレスだけを引数にしてシェルを通さずに起動し、終わるのを待ちません。
- 結果は`serve.log`に1行残ります。`Opened … in the browser.`、理由つきの`Did not open … in the browser.`、プログラムを起動できなかったときの`Could not open …`のどれかです。
- サーバーの起動と同じく、ブラウザーを開くのは`agboard`のコマンドラインだけで、試験に組み込んだライブラリは開きません。試験は`AGBOARD_OPEN_BROWSER=0`を設定し、開く処理の試験は`AGBOARD_BROWSER_OPENER`をアドレスを記録するスクリプトに向けます。

### ポート

- 手動のサーバーは`--port`（既定は7420）だけで待ち受けます。使われているポートは`port_in_use`で、理由には使っているものを示します。データ領域の違う別のAgent Boardのサーバー（pidつき）か、別のプログラムです。
- 自動のサーバーはまず7420を試します（`AGBOARD_AUTOSTART_PORT`で変えられ、試験では0を使います）。使われていれば、OSが選んだポートで待ち受け、その理由を出します。例：`Port 7420 is used by another program, so this server uses port 52114.`
- OSやサンドボックスによる拒否（`EACCES`か`EPERM`）は`local_network_denied`です。そのほかの待ち受けの失敗は、OSのメッセージつきの`board_unavailable`です。

### 自動での停止

自動のサーバーは、次のどれかに当てはまる間は「使われている」とみなします。

- `GET /api/health`以外のリクエストが、使われない時間の上限内に届いた。
- イベントストリーム（`GET /api/events`）が開いている。ブラウザーのタブ、`wait`、答えを待つ質問がこれに当たります（待つコマンドは自分のストリームに`X-Agboard-Wait`ヘッダーを付けます。[ボードを開く](#opening-the-board)を参照）。
- 携帯モニターの接続が、開始中・接続済み・再接続中・停止中のどれかである。
- ファイルの監視が、上限内にボードかDocsの変更を見つけた。ファイルを直接編集するエージェントのために、自動Doneが働くようサーバーを残します。

上限は30分で、`AGBOARD_IDLE_TIMEOUT`で60〜86400秒に変えられます。確認は30秒ごとで、単調増加の時計を使います。上限の間使われなかったときは、まず`serve.json`を消します（新しいコマンドがこのサーバーにつながず、新しく起動するためです）。続けて新しいリクエストに`503 board_unavailable`を返し、モニターの接続を終え、`lifecycle.lock`を外し、`serve.log`に`Stopped after 30 minutes without use.`と書きます。

### stop

`stop`は、どちらの動き方でも`serve.json`の`pid`にSIGTERMを送ります。ポートが応答しなくなり、さらに`lifecycle.lock`を取れるようになってから戻るので、直後に起動した`serve`が`database_busy`で失敗することはありません。10秒たってもサーバーの終了処理が終わらなければ、`stop`は失敗します。

`stop`はデータ領域に`autostart.paused`も残し、Hookがすぐにまた起動しないようにします。待つコマンド、`serve`、`serve -d`がこれを消して、サーバーを起動します。

## リクエストの処理

リクエストは、次の順序で処理します。

1. **Hostの確認。** `127.0.0.1:<port>`か`localhost:<port>`だけを受け付けます。
2. **書き込みの保護**（書き込みのみ）。`Origin`・`Sec-Fetch-Site: same-origin`・`X-Agboard-Token`がすべて一致しなければなりません（[セキュリティモデル](./security.md#ブラウザからの書き込み)を参照）。これらの検証は対象データを検索する**前**に行うため、不正なリクエストからデータの存在を探ることもできません。
3. **操作。** 読み込みはメモリ上の索引から返します。書き込みはプロジェクトの書き込みロックを取って最新のファイルを読み、`task.json`と`TASK.md`を一組で確定し、何かが変わったときだけ再読み込みと通知を起こします（[保存と復旧](./saving-and-recovery.md#タスクの保存)を参照）。

書き込みの対象は、常にURLのProjectIdです。Webの`actor`は常に`human`で、要求から受け取ることはありません。`/api/board`のような対象のない経路、互換の別名、プロジェクトを作成・名前変更・削除するHTTP APIはありません。

[プロジェクトのドキュメント](../reference/web-api.md#プロジェクトのドキュメント)のルートは、手順3の例外です。索引とプロジェクトの書き込みロックを使わず、プロジェクトの`docs/`のファイルを直接読みます。書き込みはしません。開くルートは、プログラムの起動がディスクに触れることがあるため、ブロッキング用のスレッドで動きます。

JSONとHTMLの応答は`no-store`です。スクリプトとスタイルシートは内容から名前を付け、`Cache-Control: public, max-age=31536000, immutable`で送ります。ブラウザがgzipを受け付ける場合はgzipで圧縮して送ります。新しいビルドではHTMLが読み込む名前が変わるため、再読み込みすれば常に最新の画面になります。HTMLの応答には`Referrer-Policy: no-referrer`と`Content-Security-Policy`を付けます。スクリプトと接続は自分自身だけ、スタイルは自分自身と`'unsafe-inline'`（エディターが実行時に`<style>`を挿入するため）、画像は自分自身・`data:`・`http`・`https`です。

## Web画面の作り

- `web/`はVite・TypeScript・Reactのアプリです。nuqsが選択対象のプロジェクトをURLで管理し（`useQueryState('project', parseAsString)`）、`useBoard`がプロジェクトごとの取得・購読・読み込みを担い、一つの`useReducer`が適用中のプロジェクト・切り替え待ち・タスクの選択・ダイアログを連動させます。部品内の入力は`useState`です。ほかの状態管理やフォームのライブラリは足しません。
- 初回のプロジェクト選択はブラウザ履歴を置き換え、メニューからの選択は履歴に追加します。戻る・進むはnuqsのadapterに従います。History APIを直接使ったり、独自に`popstate`を処理したりはしません。
- 一つのアプリが二つの表示を受け持ちます。`useNarrowViewport`（`web/src/shared/lib/viewport/useNarrowViewport.ts`）が`matchMedia('(max-width: 767px)')`に従うので、幅を変えるとその場で画面が切り替わります。768px未満では、`App`は`BoardWorkspace`の代わりにスマホ幅の画面（`web/src/app/mobile/MobileBoard.tsx`）を描きます。この画面は必要になったときに読み込むので、ボードの初回読み込みは変わりません。768px以上ではPC向けのボードを描きます。初回の案内はどちらの表示でも動きます。詳しくは[初回の案内](#初回の案内)を参照してください。利用者から見た画面は[ボード](../../guide/watch/board.md#narrow-windows-and-phones)を参照してください。
- スマホ幅の画面（`web/src/pages/monitor/MonitorProject.tsx`の`MonitorScreen`）は、アプリが依存先を渡します。渡すのは、添付の読み取り先と完了条件の書き込み（`MonitorReadResolvers`）、言語とテーマの保存先（`PreferencesEndpoint`）、メッセージの読み取りと、回答・取り下げの書き込み（`MessagesApi`）、ヘッダーのプロジェクト切り替えです。ボードのアプリはボード自身のルートと、ページの資格情報（トークン、ngrokの入口ではsessionのCSRFトークン）を渡します（`web/src/app/mobile/boardEnvironment.ts`）。2つ目のアプリはなく、旧モニター専用の入口とビルドは廃止しました。
- スマホ幅の画面は、一度に一つのレーンを表示します。`LaneTabs`と`MonitorLanes`は表示中のレーンを共有するので、タブのタップとカルーセルのスワイプは食い違いません。タッチを受けるのは表示中のレーンだけです（残る二つは`inert`）。表示中のレーンを先頭から下へ引っ張ると、ボードを更新します。`usePullToRefresh`がレーン上のタッチイベントを見て、レーンの一覧が先頭にあり、最初のはっきりした動きが下向きで横より縦のときだけ始まります。カードは指にあわせて（半分の距離、最大80px）`PullIndicator`とともに動き、44pxを超えてはなすと`onRefresh`を呼びます。画面の`refreshing`が立っている間は、終わってからさらに600msの間、スピナーを表示します。スマホの画面に更新ボタンはありません。カードがスライドするのは、長押しで選ばれた後だけです（`SwipeableCard`）。ほかのカードの横方向の動きはカルーセルのものになります。カード自身は何も書き込みません。レーンのボタンはボードの移動ルートで、理由なし・`fromStatus`付きで、すぐにカードを移動します（拒否されたときは`TransientNotice`の通知を出します）。アーカイブのボタンはアーカイブの確認、バーの**アーカイブ**は一括の確認を開き、この二つの書き込みはユーザーが確認した後にだけ画面が依頼します。下部のバー（`PhoneNavBar`。設定のドロワーは`PhoneNav`が持ちます）には、ボード・メッセージ・依頼・アーカイブ・設定が並びます。メッセージは`MessagesSurface`をシートで開き、未回答の質問の数（`countMessages(...).fromAi`、0なら非表示）を示します。依頼は画面の`onAsk`を呼び、アーカイブは`kind="sheet"`の`BulkArchiveDialog`を開きます（書き込みが使えないとき、または完了のカードがないときは選べません）。設定は`kind="sheet"`の`SettingsDialog`を開きます。どちらのシートも`Surface`を使います。バーは画面の端から浮かせたドックで、下の余白を`max(10px, var(--safe-bottom))`で取るので、シェルには下の余白がありません。`PhoneNavBar`は、マウントされている間ルートに`data-phone-nav`を付け、これが`--phone-nav-height`の値を決めます（バーの固定サイズに下の余白を足したもので、`phone-nav.css`にあります。バーがなければ未設定で0pxです）。シートはすべてこの高さの上に立ちます。`.mobile-drawer`は`bottom`をこの変数の分だけ上げ、`max-height`と、キーボード対応・決定・オンボーディングの各シートの固定の高さをその分だけ下げます。バーは、開いたシートとそのバックドロップより手前に出て（`.mobile-drawer`がマウントされている間は`z-index: 60`）、モーダルなRadixダイアログが外側から取り除く`pointer-events`を`auto`に保ちます。`Drawer`は、対象が`[data-phone-nav-bar]`の内側にある外側の操作を無視するので、バーのタップは項目自身のハンドラが動く前にシートを閉じません。各項目は、自分が開かないシートを閉じてから（`View.tsx`の`closeSheets`、設定のドロワーは`PhoneNav`）自分のシートを開き、ボードはすべてを閉じます。ダイアログは背後のページを`aria-hidden`にするので、シートが開いている間、バーはアクセシビリティツリーにありません。スクリーンリーダーの利用者は、先にシートを閉じます。画面のキーボードが開いている間（`data-visual-keyboard`）はバーを隠し、キーボード対応のシートは、バーの高さを含めない自分の`bottom: var(--keyboard-inset)`を保ちます。書き込みが使えるときは、画面がボードのルート経由で送り、`useLaneOverlay`が結果を次の読み取りまで画面に残します。使えないとき（デモやサンプルデータ）は、スワイプしても何も尋ねず、何も変えません。ユーザーから見た画面は[リモートアクセス](../../guide/watch/remote-access.md#レーンを切り替える)を参照してください。
- `watchStableHeight`（`web/src/shared/viewport/stableHeight.ts`。`web/src/app/entry/board.tsx`で開始）は、ソフトウェアキーボードが開く前のページの高さを、ルートの`--stable-vh`に保ちます。入力欄にフォーカスがある間のビューポートの縮みはキーボードとみなして無視し、それ以外の変化（回転、ウィンドウのサイズ変更、ブラウザのツールバー）には追従します。CSSは`svh`を代替にして`--stable-vh`を使うので、ボードがキーボードの上の細い領域に押しつぶされません。保持した高さがビューポートより高く、しかも入力欄にフォーカスがある間は、ルートに`data-keyboard`が付きます。この印はフォーカスが変わるたびに確かめ直すので、入力欄からフォーカスが外れるとすぐに消えます。`web/src/shared/styles/ui.css`の1つの規則が、ルートに`data-keyboard`または`data-visual-keyboard`（後述の`watchKeyboardInset`）が付いている間、中央に置く全ダイアログ（既定の`top-[50%]`のままのもの。AIに依頼、エディター、回答ダイアログ、設定）に働きます。ダイアログの上端は`--visual-top`にセーフエリアを考慮した小さな余白を足した位置、`max-height`は`--visual-vh`から余白を引いた高さになり、タブレットの縦向きでも横向きでも、ダイアログが見えている領域に収まってキーボードの上に出ます。このときダイアログ自身の固定の高さは上限にすぎず、モーダルの本文は最小の高さを手放し、ヘッダーとフッターのボタンは見えたまま本文がスクロールします。タブレットのキーボードの上に残る領域は200px を切ることがあるので、キーボードが開いている間は`web/src/shared/styles/keyboard-fit.css`が、こうしたダイアログすべてに同じ詰めたレイアウトを当てます。枠、ヘッダー、フッターは余白の大半を手放し、ヘッダーとフッターのボタンは高さ32pxになり、フォーカスのある欄を含まない部分（エディターの目次、添付、受け入れ条件のドック、タイトル欄、欄の見出し、開いた質問の質問の列）は畳まれます。こうして入力中の欄に数行分の高さが残ります。ルートにどちらかのキーボードの印が付くと、`revealFocusedField`（`stableHeight.ts`）がダイアログ内のフォーカスのある欄を見える位置までスクロールし直します。ブラウザがその欄をスクロールで見せたのはダイアログがまだ高いときなので、新しいレイアウトの直後と、ダイアログのトランジションの後の2回行います。`e2e/tests/dialog-keyboard-tablet.spec.ts`は、AIに依頼、回答、タスクのエディターを、170pxの領域まで含む3つのタブレットのサイズで確かめます。キーボードがないときは、これまでどおり`--stable-vh`の中央に置かれます。スマホのボトムシートは、独自の`fitKeyboard`の規則を使います。
- ホーム画面アプリでのスマホのセーフエリアは、`web/src/shared/styles/app.css`の1か所で読み取ります。`:root`が`--safe-top`、`--safe-right`、`--safe-bottom`、`--safe-left`を持ち、それぞれ対応する`env(safe-area-inset-*)`（代替値は`0px`）です。`web/index.html`が`viewport-fit=cover`を指定するため、ページはステータスバーとホームインジケーターの下まで描画でき、マニフェストの`standalone`表示ではブラウザのバーは出ません。スマホ画面のシェル、横長画面の`.app`枠（四辺すべてに余白を取るので、横向きのiPhoneでもノッチを避けます）、ボトムシート（`drawer.css`）、キーボードに合わせるダイアログ（`ui.css`）、古いページの通知帯、合言葉の入口は`env()`ではなくこの変数を読むので、Storybookのストーリーから値を設定できます（`Pages/Monitor/StandaloneSafeArea`は59pxと34pxを設定します）。ブラウザのタブとデスクトップでは0です。
- 幅の切り替えの上には、一つのコントローラー（`useAppController`）が残ります。適用中のプロジェクト、データ層が持つSummary、ストリーム、メッセージの一覧の開閉（`useMessagesController`）はこのコントローラーのもので、二つの画面が同じものを読みます。どちらかの画面で選んだプロジェクトはもう一方でもそのプロジェクトです。ドロワー、メッセージの一覧、スクロール位置は画面ごとのもので、切り替えるとやり直しになります。`AppDialogs`のダイアログは残るので、ウィンドウを狭めたときに開いていたフォームは失われません。
- `pnpm --dir web build`は、`index.html`、入口のスクリプトとスタイルシート`assets/app-[hash].js`・`assets/app-[hash].css`、動的な分割チャンク`assets/chunk-[name]-[hash].js`としてのエディターとMermaid、さらに2つ目のViteビルドによるDocsサンドボックスのスクリプトを出力します。ボードのビルドは、チャンクごとのimport・`web/src/`のモジュール・パッケージを記した`chunk-graph.json`も書き出します。最後の手順で、すべてのスクリプトとスタイルシートの横に`.gz`を書き出します。
- 最初のスクリプトには、最初の画面に必要なものだけを入れます。カード・エピック・一括アーカイブ・設定のダイアログ、詳細パネルのMarkdown表示、スマホ画面の詳細ドロワーは`preloadable`（`web/src/shared/lib/lazy/preloadable.ts`）で分割し、最初の画面を表示した直後に取得します。表示部品が届くまで、本文はプレーンテキストで表示します。エディターのアウトラインは表示側のMarkdownパーサーで`##`見出しを読むため、CodeMirrorはエディターを開いたときにだけ読み込まれます。
- `web/test/build-contract.test.ts`は、ボードの初回読み込み（入口と、そこから静的にimportされるチャンク）に上限を設け、500 kBを超えるスクリプトは使うときだけ読み込むことを確かめます。Viteの`chunkSizeWarningLimit`は、使うときだけ読み込む大きなチャンク（MermaidのELKレイアウト、文法パーサー、リッチエディター）に合わせて1500 kBにしています。
- Rustは二つのロゴ、HTMLのテンプレート、`.gz`ファイルを埋め込みます。`build.rs`はボードのスクリプトとスタイルシートを`OUT_DIR`の表にまとめ、同じバイト列のファイルは一度だけ埋め込みます。配信するのは表にある名前だけです。ページのHTMLとファイル名から、ビルドIDも作ります。ファイルや`.gz`がない場合、またはHTMLが表にないファイルを読み込む場合は、`Run "pnpm --dir web build" first.`でビルドを止めます。画面のビルドを`cargo build`の前に行うのはこのためです。`web/dist/`はコミットしません。
- 各HTMLは`<meta name="agboard-build">`に自分のビルドIDを持ち、SSEの`ready`はサーバーの現在のビルドIDを伝えます。両者が違うとページを一度だけ再読み込みします。編集ダイアログ、送信前の回答、そのほかの操作が開いている間は、終わるまで待ちます（`useBuildReload`）。同じビルドのために一度再読み込みしたタブは、もう再読み込みしません。ビルドIDを持たないページ（Viteの開発サーバー）は再読み込みしません。
- 表示用の純粋関数（日時、並び替え、件数）は`web/src/features/*/model/`または`web/src/shared/lib/`に置いてVitestで試験し、コンポーネントはTesting Libraryで試験します。
- shadcnのRadix版部品（Dialog・Button・Badge・Input・Textarea・Label・RadioGroup・DropdownMenu）と、モニターの下から出るシート（Radix Dialogを使う`drawer.tsx`）は`web/src/shared/ui/`に置き、`cn`は`web/src/shared/lib/classnames/utils.ts`、別名は`@/* → ./src/*`です。Dialogのフォーカスはライブラリに任せ、保存中に閉じさせない・送信・入力の保持は機能側で扱います。UIのスタイルは`shared/styles/ui.css`、テーマと製品のスタイルは`shared/styles/theme.css`・`tokens.css`・`app.css`です。
- 外部のCDNやフォントは読み込みません。書体は`--font-sans`と`--font-mono`の指定だけです。
- 本文の上限・書式の検証・下書きの規則・エラーは`domain`と`file_store`の一か所に置き、CLIとサーバーが共有します。

**入力されたテキストの表示。** テキストはReactの通常のエスケープで表示し、`dangerouslySetInnerHTML`は使いません。MarkdownはReact要素にし（react-markdown・remark-gfm、`rehype-raw`は使わない）、生のHTMLは文字として表示します。有効なリンクは`http`と`https`だけで、新しいタブで開きます。タスクやエピックに添付された画像（`assets/<id>.<ext>`、`attachment:<id>`）は画像APIに解決し、外部の画像は`http`/`https`からだけ`referrerpolicy="no-referrer"`で読み込み、失敗すれば「No image」にします。Mermaidは`securityLevel: 'strict'`で描画し、挿入するのはそれが生成したSVGだけです。

**下から出るシートのドラッグ。** シート上端のハンドルをドラッグしても、Reactのstateは更新しません。`useDrawerDrag`（`web/src/shared/ui/use-drawer-drag.ts`）がポインターと引き下げ量をrefに持ち、ドラッグの開始時にシートの高さを一度だけ測り、引き下げ量を1アニメーションフレームにつき最大1回、シートの`--drawer-drag-y`とバックドロップの`--drawer-swipe-progress`に書き込みます。スタイルシートがこれらを`translate`と`opacity`に変えます。シートの高さの4分の1を超える引き下げか、24px以上を0.5px/msより速く動かすフリックで閉じます。それより短い、またはキャンセルされたドラッグは、シートが開いている間だけ有効なtransitionで元の位置に戻すので、transitionとkeyframeが同時に`translate`を動かすことはありません。閉じたシートは退出のkeyframeのために引き下げ量を保ち、開くシートは描画の前に以前の引き下げ量を捨てます。動作は[リモートアクセス](../../guide/watch/remote-access.md)を参照してください。

**エディター。** `RichMarkdownEditor`（Milkdown Crepe）は`MarkdownEditor`と同じ契約を保ちます。`value`・`onChange`・`onCursorChange`・`disabled`と、`goTo`・`focus`・`insert`を持つrefです。遅延読み込みで、その間は`MarkdownView`を表示します。有効にするのはCodeMirror・ListItem・ImageBlock・Cursor・Placeholder・LinkTooltip・Toolbar・Tableだけで、Crepeのテーマは使いません。初期値はマウント時に一度だけ渡し、`onChange`は利用者の編集でだけ呼びます。編集していない文書は元の文字列のまま保存するので、変えていないMarkdownの書式は崩れません。アップロードは保留中の添付になり、`assets/<id>.<ext>`で参照します。Mermaidのプレビューと閲覧は`renderMermaid`を共有します。`web/src/shared/rich-editor/`の中では、`RichMarkdownEditor.impl.tsx`は外部の値でセッションを作り直す境界だけを持ち、`useRichEditorSession.ts`がセッション（元の文章・編集済みかどうか・初期化前のコマンド・見出し位置・後始末）、`createEditor.ts`が機能の組み合わせ、`editorCommands.ts`が`goTo`・`focus`・`insert`・`markdown`のハンドル、`MermaidPreviews.ts`が図のプレビューを受け持ちます。図のエラー文は画面の翻訳を受け取って作ります。ハンドルのコマンドが動くのは、Crepeがエディターを作り終えた後の最初のアニメーションフレームからです。それより前のコマンドはそこまで待ちます。そのフレームでCrepeのリスト項目が描画時の選択位置を戻すため、先に実行すると`goTo`や`insert`の結果が打ち消されるからです。

**テーマ。** `web/src/shared/theme/index.ts`が、テーマの型・一覧・検証・DOMの属性を受け持ちます。テーマはモード（lightかdark）と12色のアクセントの一つです。Reactの描画前に`data-mode`・`data-accent`・`dark`クラス・`color-scheme`を同期して適用します。保存した値はPCの`preferences.json`にあり、`web/src/shared/preferences/index.ts`が`GET`・`PUT /api/preferences`で読み書きします（[共有ファイル](../reference/files.md#表示設定)を参照）。ブラウザは最初の描画のためだけに、`localStorage`の`agboard.theme`と`agboard.locale`に控えを持ちます。テーマの変更がタスクの履歴に届くことはありません。

エピック一覧は、プロジェクトのSummaryから、エピックと進捗を読みます。進捗はサーバーが`epics`と同じスナップショットから計算するので、一覧が二つの読み込みを混ぜることはありません。リモートアクセスのスマホ向けの画面には、エピック一覧はありません。幅768px以上ではPCのボードになり、エピック一覧もあります。一覧はアーカイブと`ListPane`で外枠を共有し、読み込み中・読み込み失敗・再取得失敗・空の各状態はプロジェクトのresourceから決まります。再取得に失敗しても直前に読めた行を残します。

タスク詳細（アーカイブ・モニターを含む）とエピック詳細は、`web/src/features/tasks/detail/DetailHeader.tsx`の`DetailHeader`を共有します。識別表示・操作ツールバー・閉じるボタンを共通の配置にし、閉じるボタンまでの間隔を揃えます。画面ごとの操作は呼び出し側が渡します。

### Webコードの置き場所

`web/src/`は、上から順に次の4層です。

| 層 | 置くもの |
| --- | --- |
| `app/` | 入口（`entry/board.tsx`）、ボードの`App`、プロジェクトのセッション、集約する`api.ts`、遅延ダイアログの接続、サンプルデータのモード。 |
| `pages/` | 画面ごとのフォルダー: `board/`・`archive/`・`epics/`・`monitor/`（スマホ画面の部品）。 |
| `features/` | `tasks/`・`epics/`・`projects/`・`settings/`・`docs/`（プロジェクトのドキュメントのダイアログ）・`monitor-connections/`（リモート接続のPC用ダイアログ）・`resident-sessions/`（常駐エージェントのダイアログとフッターの表示）: 一つの主題の表示、フック、計算、リクエスト。 |
| `shared/` | `ui/`の基盤部品と汎用の枠、`markdown/`、`rich-editor/`、`api/`（HTTPの共通処理とサーバーのやり取りの型）、`lib/`、`styles/`、`theme/`、`i18n/`。 |

ファイルがimportしてよいのは、自分の機能またはページと、それより下の層です。`shared/`は上の層をimportせず、機能どうし・ページどうしも直接importしません。隣の機能のものが必要な部品は、ページまたは`app/`が組み合わせて渡します。`TaskCard`は`renderEpic`、`EditDialog`は`renderEpicChip`、`EpicDialog`は`renderTask`、`Header`は`projectSwitcher`と`settings`を受け取ります。ボードの設定スロット（`app/BoardSettings.tsx`）もこうした組み合わせの一つで、設定ダイアログにチュートリアルとリモート接続の行を置き、隣にある接続ダイアログを持ちます。そのため、設定ダイアログを閉じてから接続ダイアログが開きます。2つの行は、`shared/ui`の`SettingsEntryRow`を呼ぶ薄い部品（`TutorialEntryRow`・`ConnectionEntryRow`）で、アイコンのタイル、文言、ボタンは`SettingsEntryRow`が描きます。モニターの`useBuildReload`も、入口から同じように渡します。

`pnpm --dir web check`は、Biomeの後に`web/scripts/check-boundaries.mjs`を実行します。静的import、`import type`、再エクスポート、`import()`をたどり、規則に反するimport、解決できないimport、循環importがあると失敗します。許可リストで黙らせず、共通部分を下の層へ移すか、ページで組み合わせてください。機能全体を一つのファイルから再エクスポートしないでください。エディターやMarkdown表示のような重いモジュールが最初のスクリプトに入ってしまいます。遅延importは実装ファイルを指します。

UI部品のStory、焦点を絞ったテスト、専用CSS、Story対応台帳はソースの近くに置きます。台帳では、公開された部品とStory ID、表示状態を対応付けます。ページStoryは画面全体の合成を、部品Storyはその部品が持つ状態と操作を記録します。コマンドと台帳検査の現在の範囲は[Storybook](../getting-started/setup.md#storybook)を参照してください。

## データの読み取りと更新

ボードとスマホの画面は、プロジェクトを2段階で読みます。Summary（`GET .../summary`）は、カードや一覧の行に表示するすべての内容を持ちます。サーバーは索引からSummaryを作るので、読み取りでファイルは読まれません。Detail（`GET .../tasks/{id}/detail`、または`.../epics/{epicId}/detail`）は、本文・完了条件の文章・履歴を持ちます。画面がDetailを読むのは、利用者がそのカードやエピックを開いたときだけです。応答の形は[Web API](../reference/web-api.md#summaryとdetail)にあります。

`web/src/shared/data/`のデータ層は、これらの読み取りを次の3つに分けて扱います。

- `api/`: 契約の型と、DetailのNDJSONストリームの解析部です。ストリームは`complete`行を受け取った後にだけ受理します。
- `core/`: Reactに依存しないコードです。`ResourceStore`は、Summaryと、タスクやエピックごとのDetailのセクションを保持します。`RefreshScheduler`は150msの間に届いた通知をまとめ、同じリソースへの要求を1回の取得にまとめ、バックグラウンドの取得を同時に2件までにし、通知で示されたセクションだけを取得します。`ChangeInvalidator`は`changed`イベントを、安全な範囲で最も小さい無効化に変えます。`EventConnection`はイベントのストリームを開いたり閉じたりします。
- `react/`: 画面が使うフックです。`useSummary`・`useTaskDetail`・`useEpicDetail`・`usePresentationHold`などがあります。

キャッシュには固定の上限があり、時間による期限切れはありません。Summaryは直近4プロジェクトの分を、プロジェクトごとに1つずつ保持します。タスクのDetailは60件・8 MiBまで、エピックのDetailは20件・4 MiBまで保持し、上限を超えたら最も長く使われていないものから捨てます。上限は`web/src/shared/data/core/limits.ts`にあります。

**更新の保留。** ダイアログ（エディター、プレビュー、そのほかのモーダル）が開いている間は、自動更新で画面が変わらないようにしています。データ層は、ダイアログが開いている間は更新を保留し、最後のダイアログが閉じてから3秒後にまとめて適用します。PCのボード横の詳細・アーカイブ・Epicのパネルは更新を保留しません。ボードと開いているパネルはストリームに追従し、変更が名指しした部分のうちパネルが表示しているものを読み直します。保留の間もイベントのストリームは開いたままですが、データは取得しません。保存と回答は保留を待たず、すぐに適用します。`request`の項目を含む`changed`（タスクが待っている質問が変わった）も同じで、そのSummaryと名指しされた部分をすぐに取得します。ほかの保留中の更新は、そのまま待ちます。PCのボードには手動の更新はありません。ページを再読み込みすると、すべてを読み直します。

**メッセージ。** Summaryの`messages`は、プロジェクトの開いているメッセージの一覧です（[Web API](../reference/web-api.md#summaryとdetail)を参照）。**メッセージ**の帯（`MessageBand`）が件数を示し、一覧（`web/src/features/tasks/messages/`の`MessageCenter`と`MessagesSurface`）が「AIからの質問」と「あなたの依頼」のタブで表示します。3つ目のタブ**サマリー**（`SummaryList`と`useSummaries`）は、プロジェクトの定期サマリーを一覧にします。サマリーはSummaryには含まれず、一覧を開いたときに`GET .../summaries`で読み、プロジェクトの`messages`リソースに`summary`ファセットが付いた`changed`イベントのたびに（データ層の`subscribeChanges`で）読み直します。削除（`POST .../summaries/{id}/dismiss`）は項目をすぐに隠し、サーバーが拒んだときは戻します。このタブに既読の状態はなく、スマホのバーのバッジはこれまでどおり質問だけを数えます。`?project=<id>&messages=summary`のリンクは、このタブで一覧を開きます。一覧はPCではモーダル、スマホ画面では下からのシートです。開いているだけの一覧は更新を保留しません。回答された・受け付けられた・取り下げられたメッセージは、その場で差し替わるか、閉じます。スマホ画面では、一覧か**AIに依頼**のエディターが開いている間はビルドの再読み込みを待ちます。書いている途中の回答が消えてしまうためです。画面については[判断依頼](../../guide/delegate/decisions.md#メッセージの一覧)を参照してください。

**Markdownの描画。** サーバーは本文を、トップレベルのMarkdownブロックに分けます。小さいブロックは隣と約2,000文字まで結合しますが、リスト・表・コードフェンス・引用は分割しません。Mermaidのフェンスは単独のブロックです。画面は、ブロックを順番に描きます。40ブロック以上、または5,000文字以上の文書は仮想化します。画面の近くにあるブロックだけをマウントします。仮想リストは別のチャンクで、そうした文書を表示するときに読み込まれます。判断依頼の質問（`DecisionQuestion`）と履歴の理由（`HistoryTimeline`）も、本文と同じブロックの描画部品を使います。

**ボードの詳細タブ。** 詳細パネルは、開いているタブが表示する内容だけを読みます。「説明」と「完了条件」のタブは`document`セクションを、「履歴」タブは`history`を読みます。「エピック」タブは、初めて開いたときにエピックの本文を読みます。履歴タブの件数は、履歴の読み込みが終わってから表示されます。

## 画面での失敗時の振る舞い

**保存と回答**

- 作成・移動・回答を楽観的に反映することはありません。画面は成功を待ち、失敗したら入力と選択を保って再試行できるようにします。
- 質問や依頼の全文は、その行を開いたときに`GET .../messages/{id}`（`web/src/features/tasks/messages/api.ts`）で読みます。Summaryの`messages`が持つのは最初の1行だけです。タスクの`openQuestionIds`は、そのタスクが待っている質問の一覧で、**質問に回答する**のボタンは、その最初の質問で一覧を開きます（`useMessagesController`）。画面については[判断依頼](../../guide/delegate/decisions.md)を参照してください。
- 答えはページに保持しません。`MessagesSurface`の**回答を送る**は、質問1件を`{answers:[{questionId, choiceId?, text?}]}`として`POST .../messages/answers`で送り、一覧に戻って、画面がすぐにプロジェクトを読み直します。再読み込みをまたいで残るものはありません。選択肢のある質問は選択かメモの少なくとも一方が必要で、選択肢のない質問はメモが必要です（`web/src/features/tasks/messages/model/messages.ts`の`canSendAnswer`）。
- 409（`question_answered`・`question_withdrawn`・`message_closed`）では何も保存されず、画面は、その質問がほかの場所で回答されたか取り下げられたと伝えます。行を開いている間にメッセージが一覧から消えたときは、一覧に戻します。送信に失敗したときは、選択とテキストを残して再試行できるようにします。再送時に重複かどうかは判定しません。最初の回答が確定するので、成功の後の再送は`question_answered`で失敗します。
- 人の依頼は**AIに依頼**の入力画面（`web/src/features/messages/ask/`）で書きます。PCではモーダル、スマホ画面ではシートで、チャットの入力欄のような作りです（プレーンテキストの入力欄、**画像**と**依頼する**のツールバー、その上のサムネイル。[依頼を送る](../../guide/watch/editing.md#依頼を送る)を参照）。キーボードへの収め方は、画面ごとの規則ではなく共通の仕組みです。アプリは`watchKeyboardInset`を一度だけ起動し（`web/src/app/entry/board.tsx`、`watchStableHeight`の隣）、共通の`Drawer`には任意で付ける`fitKeyboard`の型（`.mobile-drawer--fit-keyboard`、`web/src/shared/ui/drawer.css`）があります。すべての`Surface`のシートがこれを使うので、AIに依頼のシートもメッセージのシート（開いた質問とその回答）も、同じ見た目とキーボード時の動きになります。`watchKeyboardInset`（`web/src/shared/viewport/keyboardInset.ts`）が、ビジュアルビューポートから`--keyboard-inset`、`--visual-vh`、`--visual-top`を保ち、ビジュアルビューポートとウィンドウの両方のスクロールに追従し、キーボードがページを覆っている間、つまりビジュアルビューポートがレイアウトビューポートより低く、しかも入力欄にフォーカスがある間は、ルートに`data-visual-keyboard`を付けます。ピンチズームやブラウザのツールバーでビジュアルビューポートが小さくなっただけでは印を付けないので、中央のダイアログは中央のままです。キーボードが開いている間、シートは見えている領域に上下の両端で固定されます（上端はステータスバーのすぐ下の`--visual-top`、下端はキーボード）。そのためボードのヘッダーを覆い、入力欄が増えた高さをすべて使います。キーボードが開いていても閉じていてもシートの見た目は変わらず、ハンドルとヘッダーは共通のドロワーより詰めてあります。`--keyboard-inset`だけ下へずらした、ぼかしのない2つ目の`box-shadow`が、シートの下のSafariがアドレスのピルやフォーム用のバーを描く帯をシートの面の色で塗るので、ボードが透けません。`sendRequest.ts`は、`text`と、画像1枚につき1つの`images`パートを持つmultipartの本文を一つ作り、`POST .../messages/requests`（20,000文字まで）へ送ります。エージェントがまだ受け付けていない依頼は、一覧の行から取り下げられます。
- WebのUIには、計画のレビューも開始のルートもありません。AIの下書きは、下書きのバッジが付いた未着手の通常のカードで、エージェントが、その質問に回答がそろったあとにCLIで自分で開始します（[下書き](./tasks-and-states.md#下書き)を参照）。計画を変えたいときは、人が下書きを編集するか、依頼を送ります。
- `web/src/features/tasks/answer/`の`DecisionQuestion`と`DecisionAnswerFields`が、一覧に出す質問と回答の欄を描きます。答えの送信中も、移動などのほかの操作はできます。

**下書きと編集**

- タスクとエピックのプレビュー（`web/src/app/dialogs/TaskPreviewDialog.tsx`のタスク用と、エピック用のプレビュー）は、最初の変更で下書きに入ります。下書きに入る前に、開いたときの内容とサーバーが返す内容を比べます。違うときは保存を止め、入力を残します。比較では、エージェントの状態変更でも動く`updatedAt`を使いません。`invalid_state_for_draft`は稼働中として扱います。
- それ以外のWeb編集は保存時の競合検出を行わず、後から保存した内容を優先します。下書きになる前に読んだ内容でエージェントがタスクを上書きすることや、複数のタブでの編集は防げません。
- 変更のないプレビューは、カードに追従します。`useStreamSubscriptions`（`web/src/app/model/useStreamSubscriptions.ts`）は、アクティブなプロジェクトの変更通知をすべてプレビューに渡し、プレビューはカードかエピックを読み直して比べます。カードが稼働中になるか、アーカイブされると読み取り専用になり、稼働が止まると戻ります。追従は、ボードの更新の遅延を待ちません。
- 人が下書きの確定を忘れると、エージェントはそのタスクを動かせません。画面とJSONの`draft`で分かります。
- 読み込めない外部の画像は「No image」を表示し、ほかを妨げません。

**プロジェクトの切り替え**

- 切り替えでは、前のプロジェクトのタスク表示と選択状態をクリアします。ボードの読み込みに失敗してもURLの対象を保ち、再試行できるようにします。プロジェクトの一覧の取得に失敗したら、古い一覧から推測せず、全体のエラーと再試行を表示します。
- 遅れて届いたボード・保存・再取得の応答は、現在の対象IDと要求番号に合うときだけ適用します。プロジェクトの切り替えは、進行中のすべての保存が終わるまで待ちます。
- 入力中や保存中の戻る・進むは最新のURLの対象を保留し、完了か取り消しの後に適用します。
- 名前変更の後も、開始済みのフォームとURLは同じIDを使います。選択中のプロジェクトが削除されたらその旨を表示して別のプロジェクトの選択を促し、最後の一つが削除されたら作成を案内します。

**アーカイブ**

- ブラウザは成功まで確認を開いたままにし、ネットワークの失敗の後は再試行できるようにします。保存中は二重送信・閉じる・切り替えを止め、開始時のIDや要求番号が違う遅れた応答を捨てます。
- 削除での404は再取得して、タスクがすでにないことを示します。ネットワークの失敗を削除の成功として扱うことはありません。空・読み込み中・一覧の失敗と再試行・切断の状態は、アーカイブの画面にも適用します。

**設定**

- 言語とカラーテーマは、ブラウザではなくPCの一つのファイルに保存し、このPCのすべてのブラウザとスマホがその値を使います。ファイルがない・不正・読めない場合は既定（英語とライトブルー）に戻し、ブラウザやOSの言語や配色は使いません。
- 起動時、ページはブラウザの控えで描画してから、`GET /api/preferences`を読みます。PCの値と違えば、ページはPCの値に切り替えます。正しいのはPCの値で、ブラウザの控えは表示が一瞬ずれるのを防ぐためだけに使います。
- `preferences`イベントは、開いているすべてのページに変更をすぐに反映します。再読み込みは要りません。ページは、すでに新しい版を表示していれば、遅れて届いた古い応答やイベントを無視します。
- 保存に失敗した場合（`invalid_preferences`・`preferences_unavailable`、または接続できない場合）も、選んだ設定は今のページに反映します。設定のダイアログには保存の失敗を表示し、PCの値は変えません。日本語の翻訳キーがなければ英語の文言を表示します。設定の失敗でボードのデータが変わることはありません。
- 詳細欄の幅は、保存する設定には含みません。`agboard.detailWidth`の別のキーでブラウザごとに保存し、値がない・不正なときは既定の幅に戻します。

### ドキュメントのダイアログ

ダイアログのデータは`DocsDialogContainer`（`web/src/features/docs/ui/`）が持ちます。画面と状態は[利用者ガイド](../../guide/watch/docs.md)で説明しています。

- ダイアログはファイルを表示するだけです。`useDocsTree`は、ダイアログを開いたときにツリーを取得します。`useDocument`はファイルを選ぶたびにそのファイルを取得し、選択の間で何も保持しません。読み込みごとにIDを付けて表示部品のキーにします。Markdownは`disabled`の`RichMarkdownEditor`、`.mdx`は`MdxFrame`（サンドボックスのページ）、画像は`FileViewer`で表示します。フロントマターは`splitFrontmatter`（`shared/markdown/frontmatter.ts`）で分け、本文の上に表示します。
- **エディターで開く**は`docs/open?path=`を送り、サーバーがそのファイルをコンピュータのアプリで開きます。
- ダイアログは`useDocsFollow`でファイルの変化に追従します。アプリは`subscribeDocs`を渡します。これは、ストリームのそのプロジェクトの`docs`の通知と、ストリームの再接続（`sync`）を呼び出しに変えるものです。呼び出しのたびに、ツリーを読み込み中の状態にせずに読み直します（`refresh`）。開いているファイルがツリーになければ`deleted`です。あれば`useDocument.refresh`で読み直し、`revision`が違うときだけ表示を置き換えて`updated`とします。通知は時刻付きでフッターの左（シェルの`footerStart`）に出し、そのファイルにだけ付きます。ドキュメントはボードのデータではないので、モーダルによる更新の保留を待ちません。
- リンクでボードの画面が移動することはありません。Markdownの本文のリンクのクリックは`DocumentPane`が拾い、`.mdx`の本文のリンクはサンドボックスのページが`{type: 'link', href}`を送ります。`resolveDocsLink`（`features/docs/model/docsLink.ts`）が`href`をファイルのフォルダとツリーに照らして解決します。一覧にあるファイルはそのファイルを選び（フォルダへのリンクはその`README.md`）、`http`と`https`は`noopener,noreferrer`で新しいタブに開き、一覧にないファイルへの相対パスはフッターに「リンク先のファイルが見つかりません。」を出します。ページ内のアンカーとほかのスキームは何もしません。こうして選んだファイルは、`DocsFileTree`が上のフォルダを開いて表示位置までスクロールします。
- 相対パスの画像は`resolveRelativeImage`（`shared/markdown/resolveRelativeImage.ts`）がファイルのフォルダを基準に解決し、画像のルートへつなぎます。自分の添付や安全でないスキームは、ここに届きません。
- ヘッダーの**ドキュメント**は、ボードにだけ表示します。ボードは`app/`でコンテナをプロジェクトをキーにして組み立てるので、プロジェクトを切り替えると最初からになります。ダイアログは初めて使うときに読み込みます。

## プロジェクトをまたぐ読み込み

`ls --all-projects`は全プロジェクトを順に読みます。各プロジェクトは並行する保存の前か後の状態で返り、プロジェクトをまたいだ一貫性はありません。データ領域を作らず、通知せず、ファイルを変えません。データ領域がなければ空の`projects`を返し、不正な`project.json`が一つでもあれば、部分的な出力はせずエラーだけを返します。

## 初回の案内

案内は、すべてブラウザの中で動きます。サーバーが持つのは、データ領域がこの案内をすでに見たかどうかという1点だけです。`GET /api/onboarding`は`unseen`、`completed`、`skipped`のいずれかを返し、`POST /api/onboarding/seen`は`completed`または`skipped`を記録します（[Web API](../reference/web-api.md)）。案内についてそれ以外は何も保存せず、ロックも取得も要りません。そのため、いくつのタブでも案内を表示でき、あるタブが別のタブを妨げることはありません。

案内の表示部品は`web/src/features/onboarding/ui`にあります。部品はpropsだけを受け取り、ボードをimportしません。`web/src/app/onboarding`の制御（`useGuide`）は、手順（`request`、`planned`、`question`、`started`、`done`）と、`started`で実行中のカードを1.8秒見せ続ける保持を持ち、その手順のサンプルカードを返します。依頼を書いている間はカードがなく、続いて1つのエピックに属するAIの下書き3枚（1枚目は質問で回答待ち）、計画の開始後の状態、3枚とも「完了」の状態の順になります。カードは`guideSamples.ts`で作ります。実際のタスクが持ちえない負のIDを持つ素の`TaskSummary`で、案内の開始時の画面の言語で作ります。ボードには書き込まないため、件数にも一覧にもリクエストにも現れません。`GuideLayer`は部品をボードに結び付けます。案内が指すレーンを測り、スポットライトの中に製品自身の`TaskCard`でエピックのラベル付きのサンプルカードの写しを描き、実際のカードはその下で暗いままにします。`App`は、幅の切り替えより上でこの層を別チャンクとして読み込みます。そのため案内のコードはボードの初回読み込みに含まれず、一つの制御が二つの表示を受け持つので、幅が変わっても案内は同じ手順のままです。

案内の提示は、プロジェクトを読み込むごとに1回です。ボードが表示できる状態（ほかの操作・回答・エピック画面・アーカイブ画面が開いていない）で、`GET /api/onboarding`が`unseen`を返すと、制御は最初の画面を表示します。**スキップ**と**ガイドを終了**は案内を閉じ、提示した案内なら`skipped`を記録します。**完了して始める**は`completed`を記録します。設定から表示した案内を途中で終えたときは、何も記録しません。設定ダイアログの**チュートリアル**の行は`requestTutorial()`を呼び、`useTutorialReplay`はボードが案内を表示できるようになるまでこの依頼を保持します。その後は、サーバーの状態にも他のタブの動きにもかかわらず、リクエストなしで同じ画面に最初の画面を表示します。読み取りに失敗したときは何も表示せず、記録に失敗したときは無視します。案内は閉じたままになり、次の機会にもう一度提示されます。リクエストは`authHeaders()`を付けるため、ngrokの入口を通したセッションでも同じように動きます。

依頼と質問への回答はブラウザの中で完結します。`request`の手順では、層が製品自身の`AskAiDialog`（スマホではシート）を、サンプルの依頼を入力した状態で開きます。送信の処理は依頼を送ったと制御に伝えるだけで、何も送信しません。その後、1枚目のカードは回答待ちと**質問に回答する**を表示し、このボタンが`SampleAnswer`（`web/src/app/onboarding/SampleAnswer.tsx`）を開きます。製品と同じメッセージの一覧（`MessagesSurface`）に、案内自身の文面と選択肢を入れた質問を1件だけ置いたものです。選択肢を選んで送ると、制御に計画を開始させるだけです。何も送信せず、回答も残しません。

スポットライトの枠の高さは、中のカードの高さに合わせます。ただし、下端が案内パネルより24px上に収まるよう上限を設け、それより高いカードは枠の中でスクロールします。

スマホ幅の画面では（`App`が`PhoneGuideLink`付きの`phone`を渡します）、層はPCボードのレーンの代わりに、スマホのレーン表示にあるその手順のレーンの先頭を枠で囲みます。`usePhoneLaneRect`はレーンの`.monitor-lane__scroll`の領域を測り、先頭までスクロールした状態に保ち、レーンが画面へ滑り込む間もそれに追従します。枠の中には、スマホ画面自身の`MonitorTask`で描いたサンプルカードを置きます。リンク（`web/src/features/onboarding/model/phoneGuideLink.ts`）が運ぶのは1つだけです。案内は、その手順が指すレーンを表示するようスマホ画面に頼み、レーンとそのタブが画面に出ます。「AI に依頼」のシートやサンプルの回答シートを開いている間は、説明が画面上部の細い帯になり、舞台は何も枠で囲みません。説明とダイアログは、幅に応じてCSS（`max-width: 767px`）で切り替えます。案内のボタンはどちらの表示でも横幅いっぱいで、2つ並ぶときは行を等分します。

## 常駐エージェントの画面

設定ダイアログの**常駐エージェント**の行がダイアログを開き、共有の`StatusBar`は省略可能な`slot`を受け取ってフッターの表示を置きます。利用者に見える内容は[常駐エージェントのガイド](../../guide/delegate/resident-session.md)を参照してください。サーバーはセッションのイベントを送らないため、画面は`GET /api/projects/{id}/sessions`をポーリングで読みます。ダイアログを開いている間は2秒ごと、フッターは5秒ごと、ダイアログで変更するたび、ページが再び表示されたときです。起動・停止・モデル・自動起動のルートはローカル専用なので、ngrokの入口を通ったページ（`usesRemoteSession()`）ではダイアログも設定の行も出さず、フッターの表示は見るだけです。サンプルデータモードとデモにはサーバーがないため、どちらも出しません。狭いレイアウトにはフッターも設定の行もなく、開いたままのダイアログは、ウィンドウが狭くなるとボトムシートになります。
