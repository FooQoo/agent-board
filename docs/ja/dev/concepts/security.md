# セキュリティモデル

Agent Boardは、一人の利用者が協力的なエージェントと使うローカルのツールです。このページでは、保護する対象、各保護機能の仕組み、保護の対象外となる範囲を説明します。データを書き込む、内容を配信する、エージェントの設定に触れる変更をする前に読んでください。

## 前提と目標

- 利用者は一人です。同じマシンのエージェントは協力的で、規則を読んでそれに従います。悪意のあるプログラムからの完全な防御は目的にしません。
- 守るのは次の二つです。
  1. タスクの内容を、ネットワーク上の他人や外部のWebサイトから見られず、変えられないこと。
  2. **削除は人だけ**という線を、エージェントがうっかり越えないこと。

以下の保護機能は、この二つの目標に基づいています。ルールに従うエージェントの誤操作を防ぐだけの制限は、その範囲を明記します。

## 保護機能の一覧

| 想定するリスク | 保護の仕組み | 詳細 |
| --- | --- | --- |
| ネットワーク上の誰かがボードを開く | `serve`は`127.0.0.1`だけで待ち受ける。リモートアクセスには明示のフラグと認証機能を持つHTTPSプロキシが要る。 | [公開範囲](#公開範囲)、[リモートアクセス](./remote-access.md#認証と書き込みの保護) |
| Webサイトがブラウザにボードへ書き込ませる | すべての書き込みでHost・Origin・`Sec-Fetch-Site`・起動ごとのトークンを確かめる。 | [ブラウザからの書き込み](#ブラウザからの書き込み) |
| エージェントがデータを削除する | 削除のコマンドは端末での人のy/Nを必須にし、Web画面はアーカイブ済みのタスクだけを削除する。 | [削除は人だけ](#削除は人だけ) |
| エージェントが下書きや完了したタスクを上書きする | CLIが下書きとDoneのタスクへのAIの書き込みを拒否する。 | [下書きとDoneのタスク](#下書きとdoneのタスク) |
| タスクの文がブラウザでコードとして動く | Reactのエスケープ、生のHTMLなし、リンクと画像の許可リスト、CSP、Mermaidのstrictモード。 | [信頼できない文の表示](#信頼できない文の表示) |
| 入力を通じて管理対象外のファイルへアクセスする | パスを組み立てる前にIDを検証し、文をパスやシェルのコードにしない。 | [ファイルとパス](#ファイルとパス) |
| エージェントがプロジェクトを取り違える | すべての書き込みは、不変なProjectIdで一つのプロジェクトを指定する。 | [プロジェクトの境界](#プロジェクトの境界) |
| setupが必要以上のアクセス権を付与する | データ領域だけを加え、既存の制限は保つ。 | [エージェントのアクセス設定](#エージェントのアクセス設定) |

## 公開範囲

- 既定の`agboard serve`は`127.0.0.1`だけで待ち受け、すべての要求は`Host: 127.0.0.1:<port>`か`localhost:<port>`でなければなりません。同じマシンの利用者は認証しません。
- `--remote-port`と一つ以上の`--remote-origin`を指定したときだけ、`serve`は共通のHTTPS入口のためのリスナーを、別の127.0.0.1のポートに加えます。Caddy（LAN、HTTPSとBasic認証）かTailscale Serve（HTTPSとtailnetの規則）がそのポートに接続します。ローカルのポートは転送せず、Funnelは使いません。認証はボード・モニター・資産・API・SSE・画像のすべてにかかります。
- 画面幅によってアクセス権が変わることはありません。認証済みの利用者はどの端末でもボード全体を使え、モニターは読み取りと回答に限られます。リモートからの書き込みの保護は[リモートアクセス](./remote-access.md#認証と書き込みの保護)で説明します。

## ブラウザからの書き込み

ローカルのリスナーは、書き込み（作成・編集・下書きの切り替え・エピックの作成と更新・エピックの所属・画像のアップロードと削除・移動・回答・アーカイブ・復元・削除）を、次の**すべて**を満たすときだけ受け付けます。満たさなければ403を返し、何も変えません。

1. `Host`がローカルのループバックの条件を満たす。
2. `Origin`が`http://127.0.0.1:<port>`か`http://localhost:<port>`。
3. `Sec-Fetch-Site`が`same-origin`。
4. `X-Agboard-Token`が、この`serve`の起動時に生成したトークン（32バイトの乱数の16進表記）と一致する。トークンは`GET /`のHTMLにだけ埋め込み、`serve.json`・APIの応答・ログには出さない。

保護は対象を探す前に行い、actorは常に`human`として記録します。`POST /api/notify`はクライアントに再取得を促すだけなので、トークンは要りません。

これらの検証は、要求がブラウザのページから来たことを確かめます。ヘッダーを偽装し、HTMLからトークンを抜き出すローカルのプログラムは止められません。そのため、`agboard --help`はエージェントに削除を人に頼むよう伝え、APIを説明しません。

## 削除は人だけ

- `rm`・`project rm`・`epic rm`と、空でないプロジェクトへの`init`は、端末での人のy/Nの確認を必須にします（[CLIのガイド](../../guide/automation/cli.md#出力と確認)を参照）。端末がないとき、または`--json`のときは、確認を出さずに失敗します。確認を省くオプションはありません。
- プロジェクトの削除では、名前と、すべてのタスクとその履歴が消えることを示します。
- Web画面が物理削除するのは、書き込みの保護を通ったアーカイブ済みのタスクだけです。アーカイブはデータを保ち、物理削除はタスクのフォルダ（本文・状態・履歴・画像）を消します。利用者がほかの場所に作ったコピーには触れません。
- 最初のリリースまで破壊的な変更を許すのは、開発中の形式の変更だけです。これらの確認を免除するものではありません。

## 下書きとDoneのタスク

- CLIの`edit`・`mv`・`state`・`history add`は下書きのタスクを拒否し、人が書いているタスクを協力的なエージェントが上書きしないようにします。
- DoneのタスクへのAIの変更（編集・状態・エピック・履歴・画像）は拒否します。
- アーカイブ済みのタスクへの書き込み（編集・下書きの変更・移動・状態・回答・添付）は書き込みロックの中で拒否し、画像は読めるままにします。
- 下書きの切り替えと編集のAPIは、ブラウザの書き込みの保護を通った要求だけを受け付けます。
- `actor`（`ai`か`human`）は操作の区分で、認証ではありません。CLIでの明示の入力か、Web側の固定の`human`から決め、担当からは推測しません。

## 信頼できない文の表示

タイトル・説明・理由・回答はエージェントと利用者が書くので、画面はこれらを信頼できないものとして扱います。

- 文はReactで表示し、HTMLとして解釈しません（`dangerouslySetInnerHTML`は使わない）。Markdownは生のHTMLを文字として表示します。外部のスクリプトやフォントは読み込みません。
- 有効なリンクは`http`と`https`だけで、`noopener noreferrer`付きで新しいタブに開きます。`javascript:`などほかのスキームは文字として表示します。
- 本文の画像は、同じタスクまたはエピックが所有する`assets/<id>.<ext>`（または`attachment:<id>`）だけを、ProjectId・所有者・画像IDを確かめる画像APIで解決します。`../`・絶対パス・`file:`・`data:`・`javascript:`・別の所有者・別のプロジェクト・シンボリックリンクは表示しません。外部の画像は`http`と`https`のURLからだけ、Refererなしで読み込みます。
- 多層防御として、HTMLの応答に`Content-Security-Policy`（スクリプトと接続は自分自身だけ、画像は自分自身・`data:`・`http`・`https`）を付け、描画の不具合があっても外部のスクリプトを実行しません。分割したスクリプトもサーバー自身の`/assets/`から読み込みます。
- Mermaidは`securityLevel: 'strict'`で描画し、図の中のHTML・クリックの処理・スクリプトを無効にします。

## ファイルとパス

- 共有ファイルはOSの既定の権限で作り、秘密情報は持ちません。
- 所有パスは、ProjectId（32桁の16進）・タスクID・EPIC-ID・画像IDを検証してから組み立てます。名前や本文の文字列をパスやシェルのコードにすることはありません。
- 共有領域の絶対パスを返すのは`workspace --json`だけで、Hook・スナップショット・エラーは相対パスだけを示します。フォルダの紐付けは端末ローカルのデータ領域にとどめ、`EPIC.md`・`TASK.md`のパスはローカルのCLIとHookの出力にだけ現れ、リモート向けのJSONには出ません。
- ボード内の文章は作業データで、Hookの設定・コマンドの引数・シェルのコードとして使うことはありません。Hookと`wait`は読み取りだけです。セッショントークン・環境変数・設定の内容はスナップショットに現れません。

## プロジェクトの境界

- 毎回対象を指定することと不変なProjectIdは、協力的なエージェントがプロジェクト・タスク番号・名前を取り違えるのを防ぎます。プロジェクトごとの認証や認可ではありません。
- 次タスク待ちのセレクターは機械的な絞り込みで、承認や認可の判定ではありません。対象タスク一件を返しますが、占有せず、複数のリスナーが同じタスクを取得することも防ぎません。作業前に最新のEPIC.mdとTASK.mdを読み、既存の承認境界を守って状態を再確認します。共有ファイルは同じOSユーザーで動くプログラムから書き込めます。
- URLのプロジェクト名やIDを、身元や権限として扱うことはありません。プロジェクトを管理するHTTP APIもありません。
- `ls --all-projects`は読み取り専用で、全プロジェクトのタスクと履歴を返します。すべて同じOSユーザーで動くので、読む範囲を狭めません。書き込み・Hook・`wait`は、これまでどおり明示した一つのプロジェクトだけを対象にします。
- Hookは`cwd`に紐付いたプロジェクトの進行表だけを渡し、全プロジェクトを暗黙に選ぶことはありません。テンプレートと汎用のスキルは、プロジェクト名や絶対パスを埋め込みません。

## エージェントのアクセス設定

`setup`が加えるのは、解決したAgent Boardのデータ領域だけで、ホームディレクトリ全体やほかのフォルダは加えません。これはエージェントに利用者のすべてのボードのデータへのアクセスを与えるので、エージェントのユーザー設定に適用します。

- 既存の許可・拒否・確認の規則、許可モード、モデル、Hook、ネットワークの設定を保ちます。フルアクセス・`bypassPermissions`・Bashの包括的な許可・管理ポリシーの緩和は加えません。現在の方式でフォルダを加えられなければ、成功として報告しません。
- 退避や一時ファイルにも同じ機微な設定が含まれうるので、既存のアクセスの制限は広げません。
- プロジェクト・アプリ・組織の設定がユーザー設定より優先されることがあるので、ファイルを更新してもアクセスは保証されません。利用者はセッションで確かめます。
- 解決した絶対パスは利用者のローカルの設定にだけ保存し、共有のテンプレートやプロジェクトの文書には書きません。

## 防げないこと

以下は、このセキュリティモデルで保護の対象外としている範囲です。

- **同じOSユーザーで動くプログラム**は、共有ファイルを直接読み書き・削除でき、CLIとWebのすべての確認を迂回できます。フォルダの書き込み権限は`task.json`を物理的には守りません。
- **下書きの`TASK.md`の直接編集**は止められず、READMEとエージェントのスキルで編集しないよう伝えます。タスクやエピックのフォルダの削除、`task.json`・`epic.json`・`project.json`の編集も同じです。
- トークンを抜き出す**ローカルのプログラムからの偽装されたブラウザの要求**は、書き込みの保護を通れます。
- **外部画像の表示に伴う情報の送信。** 外部の画像を表示するたびにそのサーバーと通信し、閲覧したこととIPアドレスが伝わります。画像のURLに、タスクの内容を載せて外部のサーバーに送ることもできます。悪意のある、または乗っ取られたエージェントが書いた場合も含みます。この制限を踏まえ、利用者自身が見慣れない画像URLに注意する必要があります。
- **Done・下書き・アーカイブ済みのタスクへのAIの変更の拒否**は、協力的なエージェントの抑止で、直接のファイル編集やactorの偽装に対する認証ではありません。
- **プロジェクト横断の読み込みに基づく書き込み**は、エージェント自身が名前を書くので、`--project`の必須化では防げません。
- **ライフサイクルのロック**は、協力的なプロセスの間で二つ目の`serve`を防ぐだけで、何かを認可するものではありません。
