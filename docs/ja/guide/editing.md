# 編集と証跡

カードとエピックはMarkdownエディタで書きます。受け入れ条件は本文の下のパネルに置き、画像やテキストの証跡をカードに添付できます。エージェントは同じ内容を、プロジェクトの共有フォルダのファイルとして編集します。

## エディタでカードと計画を書く

![目次、Mermaid図、タスクリストを含み、受け入れ条件パネルを開いたカード編集画面](../../images/guide/editor.ja.png){.screenshot}

エディタは、左に目次、中央にMarkdownの本文、右にエピックと添付画像を表示します。受け入れ条件パネルは本文の下に固定されているので、本文だけが単独でスクロールします。

カードの追加、カードの編集、エピックの編集では、受け入れ条件を本文のスクロール領域の下に固定したパネルに置きます。最初は折りたたまれています。条件を編集するときは展開してください。条件が多いときはパネルの中でスクロールし、本文を操作できるようパネルの高さは制限されます。条件のIDは固定で、並べ替えはできません。目次から本文の見出しへ移動したり、受け入れ条件パネルを開いたりできます。カードの詳細では、受け入れ条件を独立した「受け入れ条件」タブで読みます。

Markdownエディタは、見出し、タスクリスト、表、コードブロック、Mermaid図、画像に対応します。ダイアログ内の変更はまとめて保存またはキャンセルします。必須の[共有Markdownファイルの形式](#共有markdownファイルを編集する)を守り、受け入れ条件にチェックを付ける前に検証結果を記録してください。画像やMermaid図をクリックすると拡大できます。

エピックのダイアログ(名称、色、計画、タスクの順序)は[エピックと進行表](./epics)、下書きは[ボード](./board)を参照してください。

## 画像と証跡を追加する

ブラウザのエディタで画像を選択、ドロップ、または貼り付けて、カードの本文に挿入できます。添付できる画像はPNG、JPEG、WebP、GIFです。CLIでは次のようにします。

```sh
agboard --project "My project" attachment add 1 --file diagram.png --actor ai
agboard --project "My project" attachment ls 1 --json
agboard --project "My project" attachment get 1 "<attachment-id>" --output diagram-copy.png
```

画像は、カードのMarkdown内で`attachment:<attachment-id>`という永続的な参照を使います。スナップショットには添付ファイルのメタデータが含まれますが、進行表とフックには含まれません。画像のバイト列はローカルファイルに保存されます。`attachment get`は既存の出力ファイルを上書きしません。

UTF-8のログなどのテキストは証跡として追加でき、返された証跡IDで読み出せます。

```sh
agboard --project "My project" evidence add 1 test-output.log
agboard --project "My project" evidence show 1 "<evidence-id>"
```

## 共有Markdownファイルを編集する

ファイルの場所を決め打ちせず、次のコマンドで調べます。

```sh
agboard --project "My project" workspace --json
```

結果には`folder`(プロジェクトの絶対パス)、`projectId`、`readme`、`tasks`、`epics`が含まれます。ファイルを編集する前に、プロジェクトの`README.md`を読んでください。

エージェントは、そのREADMEが許す範囲で、下書きではないカードの`TASK.md`とエピックの`PLAN.md`を編集できます。直接編集するときは、同じフォルダに一時ファイルを書き、元のファイルへリネームで置き換えます。ボードはファイルの変更を自動で追従します。メタデータや状態の変更にはCLIを使い、`task.json`、`epic.json`、`project.json`、`.internal/`のロックファイルは直接編集せず、カードやエピックのフォルダも直接削除しないでください。個人の絶対パスは共有ファイルに書かないでください。

### TASK履歴と受け入れ条件のfrontmatter

`task.json`には現在のレーンや担当などのカードメタデータを保存し、形式の版は2です。履歴は保存しません。カードの本文・受け入れ条件・操作履歴の正本は`TASK.md`です。`PLAN.md`は従来の形式を保ち、操作履歴はカードだけに保存します。

TASK.mdとPLAN.mdは、受け入れ条件をファイル先頭のYAML frontmatterに持ちます。その後ろの本文は自由なMarkdownで、見出しは必須ではありません。新しいカードの入力では`history`を省略するか空のリストにできます。カード作成時にAgent Boardが最初の`created`イベントを追加します。

```markdown
---
acceptance:
  - id: AC-1
    text: The setup guide covers the supported installation steps.
    done: false
  - id: AC-2
    text: Deleting a card asks for confirmation.
    done: true
history: []
---

## Background

Any headings and text you need.
```

各条件は3つのキーを持ちます。`id`(`AC-`に先頭ゼロのない正の数が続く形で、ファイル内で一意)、`text`(前後の空白を除いて1〜2,000文字)、`done`(`true`または`false`)です。frontmatterのほかのキーは、ボードがファイルを書き込むときも保持されます。frontmatterのない`PLAN.md`には条件がなく、全文が本文になります。形式の版が2の`TASK.md`には、`acceptance`リストが空でも、有効なトップレベル`history`リストが必要です。

カードの操作があると、Agent Boardはレーンやエージェント状態の変更、質問と回答、アーカイブや復元などの履歴をTASK.mdへ追記します。画面上の状態変更も同じMarkdown履歴へ書かれ、カードの履歴タブに表示されます。通常の本文・受け入れ条件編集は最新の履歴を保持し、編集入力から履歴を変更しません。操作履歴は画面または`show`/`snapshot`で確認し、詳細な作業メモや証跡への参照は自由なMarkdown本文に記録します。

frontmatterを読み取れない場合(YAMLの誤り、キーの欠落、IDの重複、空のtext)、ボードはファイル、項目、理由を問題として報告します。そのカードは進捗を表示せず、本文を全文表示します。ボードが修正のためにファイルを書き換えることはありません。

### 条件のチェックと自動で完了

条件は、検証したあとにだけ`done: true`にし、結果と証跡を本文(たとえば実行記録の節)に記録してください。`agboard serve`の実行中は、下書きでなくアーカイブされていない、有効な条件を1件以上持つAI担当の未着手または進行中のカードが、すべての条件を達成すると自動で完了へ移ります。サーバーは起動時にも既存のカードを確認します。待機中のカードは回答されるまで待ちます。ユーザー担当のカード、下書き、不正な受け入れ条件データ、条件が空のカードは自動では完了しません。条件のチェックを外さずにカードを再開すると、再び完了することがあります。エピック自身の条件は別に確認され、タスクが完了してもチェックは自動では付きません。

### エピックの優先順

エピックのfrontmatterには、重複しない正のカードIDの`priority`リストも置けます。ボードのレーン順とは独立に、エピックの進行表とCLIの進行表の順序を決めます。

```yaml
priority: [3, 1, 2]
```

新しいカードとエピックは、空の`acceptance`リストで始まります。新しいカードの形式の版は2です。この版は形式の版が1のタスクファイルを読み込まず、移行せず、未対応として報告してファイルを変更しません。既存ボードでこの版を使うときは、ユーザーが旧データを削除してから新しいカードを作成します。Agent Boardが旧データを自動削除・初期化することはありません。形式の版が1のメタデータと組になったタスクファイルは、古い`## Work`や`## 作業内容`形式を含め、形式にかかわらず未対応で変換されません。エピックの計画は従来の動作を保ちます。
