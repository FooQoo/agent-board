# モバイルモニター

モバイルモニターは、スマートフォン向けのボード表示です。席を離れているときに、進捗を確認したり、エージェントの質問に回答したりするために使います。このページでは、モニターの表示、ngrokでスマホから接続する方法、動作の確かめ方を説明します。

## モニターに表示されるもの

モニターでは、タスクが未着手・進行中・完了に分かれて表示されます。AI担当のタスクにはエージェントの状態が表示され、未着手または進行中で回答待ちの質問がある場合は、タスク上に回答フォームが表示されます。モニターから行える書き込み操作は、この質問への回答だけです。

タスクをタップすると、画面下部から詳細パネル（ドロワー）が開きます。**本文**・**受入条件**・**履歴**・**エピック**の4タブがあり、左右のスワイプでも切り替えられます。受入条件タブには、そのタスクの条件だけが表示されます。エピックの参考条件は詳細本文で確認します。エピックタブでは、ほかの場所に表示済みのラベルやタイトルを繰り返さず、エピックの詳細を表示します。

![本文タブを開いたタスクのドロワーと、4つのタブを表示したモバイルモニター](../../../images/mobile.ja.png){.screenshot--narrow}

各タブは個別にスクロールできます。横スワイプでは、タブの内容と選択中のタブを示す下線が一緒に動きます。タブ内の操作が、外側の画面の操作を引き起こすことはありません。ドロワーを閉じるには、上端のハンドルを下へドラッグします。ドロワーはドラッグに追従して動きます。

エピック一覧は、モニターを開いたときにプロジェクトごとにまとめて読み込み、ページを開いている間は保持します。タブを切り替えるたびに取得し直すことはありません。最新の一覧を取得するには、ページを再読み込みしてください。初回の取得に失敗した場合は、再試行ボタンを使えます。

モニターのHTMLとAPIレスポンスはキャッシュされません。スクリプトとスタイルはブラウザに保存されるため、2回目以降はページとデータだけを取得します。オフライン用のスナップショットキャッシュやService Workerはありません。

新しいバージョンをインストールして`agboard serve`を再起動すると、開いているモニターは自動で再読み込みし、新しい画面に切り替わります。回答を入力している間は、送信するか入力を消すまで待ちます。切断中は接続状態を画面に表示します。

## 始める前に

ngrokのアカウントと、そのauthtokenが必要です。トークンはngrokのダッシュボードからコピーします。Agent Boardは、ngrokのTraffic Policyの機能（無料のアカウントでは使えないGoogleサインイン（OAuth）を含む）を一切使わずにアドレスを開きます。そのため、無料のアカウントでもモニターを動かせます。そのほかのngrokのプランの上限や規約は引き続き適用されます。

Agent Boardは、ngrokを使って、モニターだけにつながる公開のHTTPSアドレスを開きます。ボード全体は`127.0.0.1`のままです。ボードをインターネットに公開したり、ルーターのポート転送を使ったりしてはいけません。HTTPSはngrokで終端されるため、ngrokは通信の内容を処理できます。PCとスマホの間のエンドツーエンドの暗号化ではありません。

## 合言葉でモニターを守る仕組み

モニターは、4桁の合言葉で守られます。Agent BoardはGoogle認証もngrokのサインインも使わず、許可するアカウントの一覧も持ちません。

- 接続を開始するたびに、OSの乱数源から`0000`〜`9999`の新しい合言葉を作ります。合言葉はメモリーだけに置かれ、ファイルへの保存、ログへの出力、モニターのページへの埋め込みは行いません。
- 合言葉を見られるのはPCだけです。**接続中**のダイアログのアドレスの隣と、`agboard serve --monitor ngrok`の起動行に表示されます。
- スマホはアドレスを開くと合言葉を求められ、合言葉が正しくなるまでボードの内容は何も表示されません。接続は最長12時間続き、それを過ぎるとスマホはもう一度合言葉を求めます。
- 続けて5回間違えると、モニターは正しい合言葉も含めて、それ以上の合言葉を受け付けなくなります。接続を停止してもう一度接続する（または`serve`を再起動する）と、新しい合言葉になり、間違いの回数も数え直されます。

4桁の合言葉は10,000通りしかないため、アカウントでのサインインより弱い守りです。5回までという制限、ngrokがランダムに選ぶアドレス、開始ごとに変わる合言葉で当て推量を難しくしていますが、アドレスを秘密にしておくことの代わりにはなりません。アドレスと合言葉は、パスワードの組のように扱ってください。

- アドレスやQRコードを、人目のある場所で共有しないでください。
- 使わないときは接続を停止してください。
- 固定のアドレスが必要でなければ、「**ngrokドメイン（任意）**」は空のままにします。ngrokがランダムに選んだアドレスは見つかりにくくなりますが、それを秘密として頼ることはできません。

ngrokはAgent Boardが確認できるものを何も付けないため、モニターは自分で二つを確認します。要求が公開アドレスとちょうど一致していることと、合言葉です。ngrokはHTTPS接続を終端して通信の内容を見られるうえ、ngrokアカウントの管理者はアドレスの提供方法を変更できます。合言葉は、これらに対する守りにはなりません。

すでにPC上で動いているプログラムは、ngrokを通さずに、モニターのローカルのポートへ直接要求を送れます。何かを読むには合言葉が必要ですが、5回の試行を使い切ることで、停止してもう一度接続するまで、スマホからモニターを使えなくできます。Agent BoardはPCを使う人を信頼する前提のため、これに対する追加の防御は設けていません。信頼できるPCでだけ接続を動かしてください。

## PCから接続する

1. ボードを開き、**設定**を開きます。**モバイル接続**で**設定する**を選びます。
2. **ngrok認証トークン**に、ngrokのauthtokenを入力します。
3. トークンを保存するかどうかを決めます（[トークンの保存先](#トークンの保存先)を参照）。
4. 「**ngrokドメイン（任意）**」は、ngrokにアドレスを選ばせるなら空のままにします。同じアドレスを使い続けたいときは、`your-name.ngrok.app`のような予約済みのホスト名を入力します。
5. **保存して接続**を選びます。

接続中は、ダイアログに「**ngrokに接続しています…**」と表示されます。準備ができると、**接続中**と**スマホ用URL**、**スマホ用の合言葉**、QRコードが表示されます。**URLをコピー**でアドレスをコピーできます。QRコードが運ぶのはアドレスだけです。スマホでは合言葉の入力が引き続き必要で、PCで端末を承認する操作はありません。

合言葉が表示されるのは、接続が動いている間だけです。接続を開始するたびに新しくなるため、停止中や失敗したときの接続には合言葉がありません。

ngrokに接続できなかった場合は、設定は保存したがngrokに接続できなかったことがダイアログに表示されます。トークンとインターネット接続を確認して、**保存して再試行**を選んでください。PC上のボードは引き続き使えます。

## トークンの保存先

- 入力したトークンは、Agent Boardが動いている間だけ使われ、保存されません。
- 保存するには、接続の前に**トークンをこのPCのキーチェーンに保存する**を選びます。トークンはOSのキーチェーンに保存されます（macOSはキーチェーン、WindowsはCredential Manager、LinuxはSecret Service）。データフォルダには書き込まれません。
- 環境変数`NGROK_AUTHTOKEN`が設定されていれば、保存済みのトークンより優先されます。そのときダイアログには環境変数を使うことが表示され、トークン欄は空のままで構いません。
- 保存済みのトークンは、キーチェーンに保存済みと表示されます。**保存したトークンを削除**を選ぶと削除できます。
- このPCで使えるキーチェーンがない場合は、「**このPCでは保存できません（都度入力）。**」と表示され、保存の選択はできません。接続のたびにトークンを入力してください。

ドメインは、Agent Boardの内部領域に保存されます。ファイルを編集する必要はありません。合言葉はどこにも保存されません。

## スマホで開く

1. スマホで、URLを開くかQRコードを読み取ります。
2. 「**合言葉を入力**」の画面が表示されます。PCに表示されている4桁の合言葉を入力して、**接続する**を選びます。
3. モニターが開きます。接続は最長12時間続きます。それを過ぎた場合や、PCで接続を止めて開始し直した場合は、もう一度合言葉を求められます。

ngrokの無料プランでは、スマホから初めて開くときにngrokの警告ページが表示されます。「Visit Site」を選ぶと、モニターが開きます。初回は、`/monitor/`などのパスを付けず、アドレスをそのまま開いてください。警告ページを通ったあとにアドレスへ戻り、そこからモニターが開きます。このブラウザで警告を通す前に`/monitor/`へ直接アクセスすると、白い画面のままになることがあります。

アドレスを知っているだけではボードを読めません。間違った合言葉は、残り回数を示さずに拒否されます。続けて5回間違えると、「間違いが続いたため受け付けを止めました」と表示され、それ以上は受け付けられません。PCで接続を停止してからもう一度接続すると、新しい合言葉になります。接続が停止中と表示された場合は、PCを確認してください。

## 停止と再接続

接続中のダイアログで**停止**を選ぶと、接続を閉じます。スマホはボードを読めず、回答も送れなくなります。次にAgent Boardを起動したときも、接続は始まりません。再び接続するには、**モバイル接続**を開いて入力を確認し、**保存して接続**を選びます。

PCがスリープした、ネットワークが変わったなどで接続が切れたときは、停止してからもう一度接続してください。**接続設定を変更**でドメインを変えて**保存して接続**を選んだ場合も、接続が作り直されるため、スマホは新しい合言葉を入力する必要があります。

接続したままにしていた場合は、次にAgent Boardを起動したときに、環境変数かキーチェーンからトークンを使えるかぎり、自動で接続が始まります。トークンがなければ、ダイアログがトークンの入力を求めます。

## ngrokが通信の内容を残さないことを確認する

アカウントでFull Captureが有効だと、ngrokのTraffic Inspectorがリクエストの詳細を保持することがあります。Agent Boardがこれを無効にすることはできません。ngrokのダッシュボードで**Settings** → **Observability**を開き、Full Captureが無効であることを確認してください。モニターを使う前に確認します。

## コマンドラインで起動する

サーバーの起動と同時に接続を始めるには、環境変数にトークンを設定します。

```sh
export NGROK_AUTHTOKEN=<your authtoken>
agboard serve --monitor ngrok
```

予約済みドメインを使うなら`--ngrok-domain your-name.ngrok.app`を加えます。コマンドは、ローカルのアドレスと一緒にスマホ用のアドレスと合言葉を出力します（例: `Serving at http://127.0.0.1:7420/; mobile monitor at https://… with passcode 4821`。`--json`では`monitor`フィールド）。合言葉はサーバーを起動するたびに変わります。接続を開始できないときは、`serve`は終了コード1で止まります。そのほかのオプションは[CLIガイド](../automation/cli)を参照してください。

コンピューターがスリープしたりサーバーが止まったりすると、サーバーと接続が再び動くまで、モニターは使えません。

## スマホで確認する

レスポンシブなブラウザテストは狭い画面幅をカバーしますが、ソフトウェアキーボードは実機での確認が必要です。スマートフォンのブラウザでモニターを開き、待機中の質問を持つ未着手または進行中のタスクを探します。キーボードが出ても回答欄と送信ボタンを操作できることを確認し、回答を送信してください。あわせて、長い本文、受入条件、エピックのタブでのスクロール、タブの横スワイプ、ハンドルによる下方向の閉じ操作も確認します。ブラウザのエミュレーションだけでは、Safariのキーボードの挙動は確認できません。
