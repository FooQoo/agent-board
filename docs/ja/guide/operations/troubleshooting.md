# トラブルシューティング

当てはまる症状を探し、原因と対処を確認してください。コマンドは、`task_is_draft`のような短いコードでエラーを示します。すべてのコードの意味は[開発者ガイド](../../dev/reference/errors)にあります。

## ボードの表示が想定と違う

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| タスクがボードにない | ファイルが壊れている、またはサポートされない`formatVersion`を持つ。 | `agboard --project "My project" snapshot --json`を開き、`problems`を読みます。ファイル・項目・理由が書かれています。ファイルを手で直してください。Agent Boardは書き換えません。[ファイルに不備があるとき](../automation/file-format#ファイルに不備があるとき)を参照。 |
| タスクに警告が出て、条件がない | `TASK.md`のfrontmatterが正しいYAMLでない。 | frontmatterを直します。その間も本文は表示されます。 |
| エージェントが変更してもボードが更新されない | サーバーが動いていない、またはファイルがネットワークドライブにある。 | ページを再読み込みします。`agboard serve`を動かしたままにします。ネットワークドライブは、ファイルの変更を知らせないことがあります。 |
| 「切断」と表示される | ローカルのサーバーとの接続が切れた。 | しばらく待ちます。ページは自動で再接続し、ボードを読み直します。サーバーが止まっていたら、起動し直します。 |
| エージェントが止まったあともタスクが**稼働中**のまま | 稼働中はエージェントが最後に報告した状態で、リアルタイムの確認ではない。 | タスクを移すか、エージェントに新しい状態を報告させます。 |
| 質問が消えた | タスクを別の列に移すと未回答の質問が取り下げられる、またはエージェントが新しい質問をした。 | タスクの履歴タブを開き、現在の質問があれば回答します。 |

## エージェントができないことがある

| エラー | 原因 | 対処 |
| --- | --- | --- |
| `task_is_draft` | タスクが下書きで、エージェントは変更できない。 | ブラウザで下書きを確定します。その間、エージェントはほかのタスクを進められます。 |
| `task_is_done` | タスクが完了で、エージェントは変更できない。 | 作業が必要なら、ブラウザでタスクを再開します。 |
| `acceptance_unmet` | 未達成の条件があるタスクを、エージェントが完了へ移そうとした。 | エージェントに条件を検証させて達成にします。そうすればタスクは自動で完了します。 |
| `request_changed` | 質問がすでに回答された、取り下げられた、または置き換えられた。 | タスクを読み直し、現在の質問に回答します。 |
| `folder_unbound`・`bound_project_missing` | エージェントのフォルダがプロジェクトに登録されていない、またはプロジェクトが削除された。 | フォルダを登録します: `agboard project bind "My project"`。[データとバックアップ](./data#フォルダを登録する)を参照。 |
| `confirmation_required` | 削除には、端末での人の確認が必要。 | 自分でコマンドを実行します。 |
| Hookが`AGBOARD_ERROR`を示す | 進行表を作れない（プロジェクトがない、表が256 KiBを超える、サーバーに届かない）。 | メッセージが示す原因を直します。有効な進行表を取得できるまで、エージェントはボードを変更してはいけません。 |

## サーバーが起動しない

| エラー | 原因 | 対処 |
| --- | --- | --- |
| `already_serving` | このデータフォルダで、すでに別のサーバーが動いている。 | そちらを使うか、そのターミナルでCtrl+Cを押して先に止めます。 |
| `port_in_use` | 別のプログラムがそのポートを使っている。 | 別のポートを選びます: `agboard serve --port 7421`。 |
| `database_busy` | ほかのコマンドがプロジェクトの書き込みロックを5秒以上保持している。 | コマンドをもう一度実行します。 |

## スマホからボードに接続できない

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| ページが開かない | サーバーかプロキシが動いていない、またはコンピューターがスリープしている。 | 両方を起動し直し、コンピューターをスリープさせずに稼働させます。 |
| ブラウザが証明書について警告する | スマホがCaddyのローカル証明書を信頼していない。 | Caddyのルート証明書（公開証明書）だけをスマホに入れます。[CaddyでLANに公開する](./mobile-monitor#caddyでlanに公開する)を参照。 |
| ページは開くが、回答が拒否される | 開いたアドレスが、`--remote-origin`の値のどれでもない。 | 開くHTTPSのアドレスそのものを指定して、サーバーを起動します。 |
| モニターが、データが古いと表示する | 自動更新が止まった、または一部のプロジェクトを読めなかった。 | ページを再読み込みするか、開き直します。モニターは、再び表示されると取得し直します。 |

## それでも解決しないとき

- `snapshot --json`の`problems`を読みます。ファイルや形式のエラーを説明しています。
- どのデータフォルダを使っているか確かめます。CLI・サーバー・Hookは、同じ`AGBOARD_HOME`を共有していなければなりません。[データとバックアップ](./data#データの保存先)を参照してください。
- Agent Board自体を開発しているなら、[開発者向けのトラブルシューティング](../../dev/troubleshooting)が、ビルド・テスト・内部の失敗を扱います。
