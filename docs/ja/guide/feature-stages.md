# 機能の提供段階

Agent Boardの機能は、一般提供（GA）とパブリックプレビューのどちらかの段階にあります。このページでは、それぞれの段階の意味、各段階の機能、プレビューの機能を使う前に知っておきたい制約をまとめます。製品にはどちらの段階も含まれていて、すべての機能がGAというわけではありません。

## 段階の意味

| 段階 | 意味 | 意味しないこと |
| --- | --- | --- |
| 一般提供（GA） | このガイドの説明どおりに動作し、当面はその仕様で運用していく機能です。今後の変更は、機能を足す方向を想定しています。 | 不具合がないことを意味しません。互換性やサポートを無期限に保証するものでもありません。 |
| パブリックプレビュー | 試していただくために公開している機能です。今後の版で動作や仕様が変わる可能性があり、後述の制約があります。 | 機能の利用を制限したり、ライセンスを変えたりするものではありません。 |

段階は、その機能が今後どれだけ変わりうるかを表します。どれだけ入念に試験したかを表すものではありません。よく使われる機能が、それだけでGAになるわけでもありません。

## 製品内の表示

パブリックプレビューの機能は、使う前に次の注意を表示します。

> この機能はパブリックプレビューです。仕様や動作が変更される可能性があります。現在の制約はドキュメントをご確認ください。

表示される場所は次のとおりです。

| 機能 | 表示される場所 |
| --- | --- |
| [ドキュメント](#docs) | 「ドキュメント」ダイアログの見出しに「パブリックプレビュー」のバッジが付き、その下に注意文とこのページへのリンクが出ます。 |
| [常駐セッション](#resident-sessions) | 設定の「常駐セッション」ダイアログの見出しに「パブリックプレビュー」のバッジが付き、紹介文の下に注意文とこのページへのリンクが出ます。 |
| [質問と依頼](#questions-and-requests) | 画面はありません。このページとエージェントのSkillで説明します。 |

GAの機能には、この表示はありません。

## パブリックプレビューの機能

### ドキュメント {#docs}

「ドキュメント」ダイアログで、プロジェクトの`docs/`フォルダにあるファイルを一覧して読めます。機能は今も変わり続けています。

- **対応範囲:** パソコンのブラウザのボードと、リモートアクセスで幅768px以上の画面に開いたボード。ドキュメントをPCのアプリで開く操作は、PCでだけ使えます。
- **制約:** MarkdownとMDXのファイルは2 MiBまで、画像は10 MiBまでです。
- **ガイド:** [プロジェクトのドキュメント](./watch/docs)

### 常駐セッション {#resident-sessions}

常駐セッションは、Agent Boardが起動してボードに張り付かせておくClaude CodeかCodexのセッションです。ボードが、あなたの依頼、セッション自身の質問への回答、着手可能なタスクを、1つずつ送ります。

- **対応範囲:** `agboard serve`を動かしているパソコン上のClaude CodeとCodex。起動と停止は、パソコンの**設定**から行います。スマートフォンの接続からはできません。
- **制約:** セッションは人が見ていない状態で動き、操作を自動で承認します。信頼できるプロジェクトでだけ起動してください。Claude Codeの`claude`のstream-jsonと、Codexが実験的と位置づけている`codex app-server`に依存するため、これらのCLIの更新で変わる可能性があります。ボードが起動するセッションは同時に1つです。3回失敗した項目はスキップし、ダイアログに表示します。
- **ガイド:** [常駐セッション](./delegate/resident-session)

### 質問と依頼 {#questions-and-requests}

自分で開いたエージェントのセッションは、ボードに張り付いたままにできます。`agboard wait --until task`か、`wait`スキル（Claude Codeでは`/agent-board:wait`）を使うと、セッションがあなたの依頼、質問への回答、タスクを続けて受け取ります。

- **対応範囲:** Claude CodeとCodex。エージェントのSkillにある手順に従います。始めるのは、人がエージェントのセッションで行います。
- **制約:** タスクは、返された時点では確保されないため、複数のセッションが同じタスクを受け取る可能性があります。依頼と回答だけは守られていて、最初の`message accept`が有効です。ほかのセッションが受け取ろうとすると`request_accepted`になります。セッションは、あなたが中断したときか、エラーで止まったときに終わります。
- **ガイド:** [次のタスクを待つ](./delegate/agents#listen-for-the-next-task)
