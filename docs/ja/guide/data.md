# データとバックアップ

## データの保存先

既定のデータフォルダは、OSのアプリケーションデータフォルダの下の`agboard/`です。

| OS | 既定のフォルダ |
| --- | --- |
| macOS | `~/Library/Application Support/agboard/` |
| Windows | `%APPDATA%\agboard\` |

別のデータフォルダを使うには`AGBOARD_HOME`を設定します。ボードを共有するには、CLI、サーバー、フックが同じフォルダを使う必要があります。

```text
shared/
  workspace.json
  projects/<project-id>/
    README.md
    project.json
    tasks/<card-id>/
      task.json
      TASK.md
      assets/
      evidence/
    epics/<EPIC-ID>/
      epic.json
      PLAN.md
      assets/
```

`task.json`には現在のレーンや担当などのカードメタデータを保存し、形式の版は3です。本文・受け入れ条件・操作履歴は`TASK.md`に保存し、画面の履歴タブも同じMarkdown履歴を読みます。画面とCLIからの状態変更は同じ履歴へ追記されます。トップレベルの`history` frontmatterには、日時の`at`と内容の`reason`だけを持つ履歴を保存します。作業の進捗とカード操作は、ファイル・API・CLIで同じ形式です。本文には計画・検証結果・証跡への参照を記述し、時系列の履歴は記述しません。エピックの計画は`PLAN.md`に保存します。進行順はpriorityメタデータに、参考条件はMarkdown本文に記述し、エピックには履歴を保存しません。

タスクの形式の版が1と2のファイルは未対応で、アプリは問題として報告し、ファイルを変更しません。移行、旧形式へのフォールバック、旧タスクデータの削除・初期化は行いません。ほかの共有JSONファイルは形式の版が1のままです。

## バックアップと復元

バックアップや復元の前に、`agboard serve`、エージェント、ファイルへ書き込むエディタを止めてください。すべてのプロジェクトとワークスペースの形式を保つには、`shared/`フォルダ全体をコピーします。1つのプロジェクトだけなら、`workspace --json`の`folder`の値を使って、そのフォルダ全体をコピーします。サーバーとエージェントを再起動する前に、コピーを同じ場所へ戻してください。

## フォルダの登録

フォルダの登録は、データ領域の`bindings.json`に別に保存され、マシン固有のパスを含みます。同じマシンでのバックアップには、必要に応じてこのファイルも残してください。別のマシンでは`project bind`で正しいフォルダを登録します。このファイルをコミットしたり、共有のプロジェクトファイルの中に置いたりしないでください。
